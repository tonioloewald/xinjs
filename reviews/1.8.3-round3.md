# Blockers

## B1 — `redactWithin()` descends under only the FIRST spelling that contains a secret (verified)

`src/agent.ts:789`

The leaf test is `candidates.some(isSecretPath)` — correctly OR'd across spellings. The descent is `candidates.find(containsSecret)` and recurses under that **one** spelling. Any secret learned under a different spelling of the same child is emitted raw.

Reproduced three ways against `src/`:

- **Two idPaths on one array** — `read('twoIds.rows')` → `[{"id":"a1","uid":"u1","pw":"⟨secret⟩","tok":"TOK-SECRET"}]`. Both leaf reads redact correctly; only the ancestor descent leaks.
- **`describe()`, DEFAULT read-only posture** — an ordinary `bind(button, 'mixedD.rows', bindings.enabled)` yields the wiring record `"enabled":"[{…\"pw\":\"⟨secret⟩\",\"tok\":\"TOK-SECRET2\"}] ⟵ mixedD.rows"` with `"exposure":"read-only"`. Both password inputs are correctly described as `secret:true` — the surface _knows_ both paths are secret and still ships one value in cleartext through a neighbouring non-secret binding.
- **index + idPath mix** — one ordinary index-spelled control reaches it; no exotic setup needed.

The comment at `src/agent.ts:614-618` asserts "Descending from an ancestor IS covered — `redactWithin` tries every spelling — so `read('list')` is safe." **That is false**, and it is load-bearing: it is the stated reason the remaining spelling-sensitivity was accepted as a documented known gap. `SEC-2c/2d/2e` (`src/agent.test.ts:1465-1550`) each use a single spelling per array, so the suite is structurally incapable of catching this and is green with the defect present.

**Fix** (`src/agent.ts:789-790`) — make the descent match the leaf test's `some` semantics:

```
let child = clone[key]
for (const c of candidates) if (containsSecret(c)) child = redactWithin(c, child)
clone[key] = child
```

Add regression tests at **both** addresses (`read()` and `describe()`) for all three probe shapes. Correct the comment at `:774-776`.

_Incomplete fix, not a regression — before `9053066` the whole array leaked._

## B2 — Index-spelled paths bypass secret redaction in `describe()`, `read()` and `changes()`; the disclosed scope of #32 understates it badly (verified)

`src/agent.ts:610`

`extendsPath` is a pure string prefix test, so a secret learned as `rows[id=r1].pw` has no prefix relation to any `rows[0]…` spelling. Three reproduced vectors:

1. **`describe()`, read-only default** — `bind(summary, 'p6.rows[0]', bindings.text)` emits `"text":"{\"id\":\"r1\",\"pw\":\"hunter2\"} ⟵ p6.rows[0]"` in the same map that correctly reports the password input as `secret:true`.
2. **`tosi_changes`, manifest posture, entirely passive** — an ordinary index-spelled write makes tosijs's own id-path synthesis record _both_ spellings, and the drain hands them over side by side: `[{"path":"p4.rows[0].pw","value":"rotated"},{"path":"p4.rows[id=r1].pw","value":"⟨secret⟩"}]`. **The agent constructs nothing.** Verified across four write shapes — including `for (const row of app.rows) row.pw = …`, the idiom CLAUDE.md documents as _correct_.
3. **`read('p4.rows[0]')`** → `{"id":"r1","pw":"rotated"}` — an index-spelled _ancestor_ read leaking the whole row, while `read('p4.rows')` and the id-spelled leaf both redact.

**The disclosure is wrong in both directions.** `src/agent.ts:615-622`, `CHANGELOG.md:32-36` and `TODO.md:1204-1215` all say ancestor descent is covered and advise "scope them with a manifest." Case 3 refutes the first. Case 2 refutes the second — no query is constructed. And the manifest is inert both ways: `p4.rows[0].pw` is _inside_ the declared root, and declaring the manifest is precisely what flips `canRead` and turns `tosi_read`/`tosi_changes` on.

A further completeness check found the gap is **symmetric, not index-specific**: bind a password control directly at the index spelling and the asymmetry inverts — `read('app.rows[id=r1].pw')` returns cleartext while the parent read redacts. A reader following the release notes could conclude id-path spellings are the safe ones.

**Minimum honest ship:** fix or rewrite all three disclosure sites to say that _any_ differently-spelled path at or above a secret leaks its whole subtree, through `tosi_describe` in the default posture and through `tosi_changes` with no crafted query, and that a manifest does not contain it. Preferred: reuse `redactWithin`'s candidate generation, inverted, at the query side via `getArrayIdPaths`, **failing closed** if canonicalisation throws. Cheapest real containment: fail closed in the ledger drain and `boundValue` when a path's array segment is index-spelled and that array has any registered idPath.

_Not a regression — 1.8.3 narrowed the describe leak to the index-spelled half rather than creating it. The underlying deferral (#32) is defensible; what ships around it is not._

## B3 — A self-documented breaking change ships as a PATCH bump (verified)

`package.json:3` · `CHANGELOG.md:52`

`.tosi.listBinding()` now returns `[{ bind: { value, binding: 'list', options } }, template]` instead of `[{ bindList: { value, ...options } }, template]`. The CHANGELOG says so itself: _"`props.bindList` is now `undefined`. This repo's own tests did exactly that and had to be rewritten, which is the evidence that a consumer plausibly does too."_

Reproduced: `Object.keys(props)` → `["bind"]`; `props.bindList.virtual = {…}` → `TypeError`. The `^1.8.0` range is npm's default, so every consumer floats to this automatically.

`bindList` on this tuple was **documented public API**, not an internal — `v1.8.2:src/list-binding.ts` said verbatim _"The props (containing `bindList`) are applied to the container"_, plus a whole `### bindList + template — the low-level way` section, both deleted this release. Types are byte-identical across the break (`bindList?` is still an optional member of `ElementProps`), so TypeScript gives no signal.

The project's own policy names a different number. `../tosijs-coding-practices/practices/releasing.md:184`: _"breaking toward correctness — announced and documented, **in a minor** — is the right default."_ And this release's own diff adds to `TODO.md`: _"the great purge is 2.0; until then we try not to break anyone."_ Earlier CHANGELOG entries (`:200`, `:428`) carry explicit "This release deviates from semver, and says so" notes; the 1.8.3 section has none, and `TODO.md:407` (P7, document the semver deviation) is still open.

Blast radius is genuinely narrow — the documented spread usage is intact, and the one known downstream (`tosijs-ui/src/data-table.ts:2381`, `:3328`) spreads the tuple and is unaffected. But narrowness is about _how many_ are hit, not whether it happened. It is irreversible once published (this project has already had to `npm deprecate` 1.7.6 and 1.7.7 for shipped-then-discovered problems) and free to fix before publish.

**Fix:** cut this as **1.9.0**. Bump `package.json`, the CHANGELOG heading, re-run `bun run build` to restamp `src/version.ts` and `dist/`. Move the entry under `### Breaking`, not `### Changed`. `^1.8.0` still picks 1.9.0 up, so the security fixes propagate; only `~1.8.x` pinners are held back, which is correct. **Re-review scope: Tier 0 only** (version string, CHANGELOG heading, regenerated artifacts).

# Follow-ups — file to this repo's `TODO.md`

### Security / correctness

- [ ] **Secret scan cannot see inside shadow roots** (verified, major) — `src/agent.ts:731`. `refreshSecretPaths()` uses `document.querySelectorAll`, which does not pierce shadow roots. **The blessed pattern leaks:** a `Component` with `shadowStyleSpec` containing `input[type=password]`, bound the approved way (`bind(host, 'acct.password', bindings.value)`), produces `describe()` wiring `{"tag":"pf-3","value":"TOP-SECRET ⟷ acct.password"}` in the read-only default, with **no warning** (the existing warning only covers `bind()` on an element _inside_ a root). `fromDOM` works across open shadow boundaries (`composedPath`) while `toDOM` detection does not, so real typed input reaches state through a path the scan structurally cannot learn. `data-tosi-secret` on the host fixes it and is documented nowhere. Fix: walk open shadow roots in `refreshSecretPaths()`, and bound the claim in CHANGELOG/`agent.ts` for closed roots. Same caveat for never-rendered rows of a virtualised list. _Pre-existing since 1.8.0; `SECURITY-1.8.0-rc.1.md:184` notes the non-piercing walk but analyses it only as scope evasion, never as a hole in secret detection._
- [ ] **SEC-8 arrow-forgery fix applied to only 4 of ~10 string fields** (verified, major) — `src/agent.ts:834`. `stripArrows()` covers `text`, bound value, unbound live value and contenteditable text, but **not** `label` (:834, from aria-label/aria-labelledby/`<label>`/title/alt), `placeholder` (:837), `description` (:875) or `href` (:840). Both consumers scan _every_ string value (`audit.ts:88-91`, `schematic.ts:442-445`/`:470-474`), and `schematic.ts:427` uses `w.label` **raw** while `text`/`value` go through `shownValue()`. Reproduced on a fully inert element: a display-only `<div title="holiday ⟷ app.admin.token.jpg">` bound one-way gets the `↔` editable badge, emits `app.admin.token` into the SVG caption, and trips `missing-role` in the accessibility audit. `img({alt: upload.filename})` is enough. The comment at `:940-941` ("fixes every consumer at once") overstates it. Fix the four assignments plus the structural-tier heading text at `:1532`; extend the SEC-8 test past bound-value/static-text. _(One correction: `record.type` is **not** forgeable — the DOM normalises `input.type`.)_
- [ ] **`autocomplete` matching is case-sensitive** (**unverified** — sanity-check first) — `src/agent.ts:661`. `autocomplete` is not in HTML's ASCII-case-insensitive selector list, and `isSecretControl` mirrors it with case-sensitive `startsWith`, so `autocomplete="CC-Number"` — legal HTML that browsers autofill as a PAN — is never learned. Fix: `.toLowerCase()` in the predicate, `[autocomplete^="cc-" i]` in the selector.
- [ ] **`secretPaths` is never cleared** (**unverified** as a test-hygiene claim; the lifecycle gap itself is confirmed by inspection) — `src/agent.ts:607`. Only ever added to (`:738`, `:1282`); `disable()` (`:1808`) does not touch it. Production consequence: a password field removed from the DOM (modal closed, SPA route change) leaves its path secret for the page's lifetime — fails _closed_, so a wart not a hole. Test consequence: the `document.body.replaceChildren()` added to `agent.test.ts`'s `afterEach` only stops _new_ registrations; already-registered paths persist across the whole `bun test` process, so a future test could assert `⟨secret⟩` for the wrong reason and pass/fail by file order. Add `_resetSecretPaths()` beside `_resetDeprecationWarnings()`, call it in the `afterEach`, correct the comment, and consider clearing in `disable()`. No test covers disable/re-enable or control removal.
- [ ] **Null list row still throws inside the binding update pass** — B3's hardening fixed `redactWithin` at the agent's address only; the same null row makes a list binding throw (`tosijs: a binding threw while updating this element…`). Verified **not** a regression (reproduces against `v1.8.2:dist/module.js`), so not a ship blocker — but it is exactly the "I fixed the instance I reproduced, not the class" pattern `18d1060`'s own commit message names.

### Efficiency

- [ ] **`tosijs/state` carries the entire DOM layer** (verified, major) — `src/xin.ts:846`. A static `import { elements } from './elements'` for two lines inside the `listBinding` accessor pulls `bind.ts`, `bindings.ts`, `css.ts`, `list-binding.ts` and the element factory into the entry whose entire reason for existing (tosijs#18, raised from react-tosijs) is DOM-free minimalism. Measured with the production Bun.build config: **45,158 raw / 16,540 gz** baseline vs **13,558 / 5,419** with `./elements` stubbed — a **67.2% gz reduction (11.1 kB)**. `src/entries.test.ts:34` already asserts `'elements' in state === false`, so the entry contractually excludes what it ships. Budget headroom is under 1 kB (`bin/bundles.ts:109-113`, 17,500 vs 16,540). Fix: `setElements()`/`getElements()` in `registry.ts` mirroring the existing `getBind`/`getOn` lazy pattern; then lower the budget. **Caveat making this a minor-version move, not a patch:** because `elements` is statically linked today, `.bind()`/`.on()`/`.listBinding()` currently _work_ for a browser-bundled state consumer; the lazy getter makes them throw. That matches the documented contract but is a real behaviour seam.
- [ ] **Secret-path matching is an unbounded linear scan, called 2–3× more per element this release** (verified, minor-at-top-of-band) — `src/agent.ts:971`. `secretPaths` grows one entry per bound secret-bearing control _instance_, and virtual-list recycling adds row spellings forever. Measured: `describe()` with 200 live elements — 4.67 ms (0 secrets) → 15.34 ms (6000); `read('app.rows')` on 5k rows — 1.38 ms (0) → **74.22 ms (400 secrets)**; `redactWithin`'s inner loop is 1.29×/1.85×/3.10× the old cost at 20/100/400. `pathParts` (`src/by-path.ts:23`) is uncached, adding 0.24 ms per 5k-row read. Both scans are zero-iteration when no secret exists, so an ordinary page pays nothing. Fix: memoise `isSecretPath`/`containsSecret` in a `Map` keyed on `secretPaths.size` (an exact generation counter, since the set only grows — this is _not_ the invalidation story that made the reverted binding-generation cache a security regression); in `redactWithin`, precompute the extending subset once per invocation and skip the id-path candidate when no member uses that spelling.
- [ ] **Deprecation prose is 286 gz bytes in the non-shakeable IIFE and is rebuilt per call** (**unverified**) — `src/elements.ts:700`.
