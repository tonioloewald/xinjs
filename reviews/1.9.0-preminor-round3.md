## Blockers (must clear before tagging)

### B-1 — `associatedLabel()` and `referencedText()` launder secret and out-of-scope values into `record.label` / `record.description`

`src/agent.ts:695` (and `:648`) · **verified by execution** · security + correctness

`record.label` has three sources (agent.ts:1239-1245). This diff guarded exactly one of them.

- **`associatedLabel` (agent.ts:695) has no guard at all** — neither secrecy nor scope. It resolves `el.closest('label')` and `document.querySelector('label[for=…]')`, both of which escape the element's own subtree, which is precisely the escape M-2 was filed about. `harvestWouldLeak` cannot see it: its DOM arm is a **subtree** `querySelector` on an `<input>`, which has no children — and `suppressHarvest` gates `record.text`, never `record.label`.
- **`referencedText` (agent.ts:648) got secrecy this round but not scope** — while its sibling B-1 fix in the same commit is entirely about scope.

Reproduced arms, manifest posture (`expose: { roots: ['sApp'] }`, the documented production floor):

| Shape                                                                        | `read()`                                                  | `describe()`                                               |
| ---------------------------------------------------------------------------- | --------------------------------------------------------- | ---------------------------------------------------------- |
| `<label for="s-in">Qty <span bound to sPriv.csrf></span></label>`            | throws `not exposed`                                      | `{"tag":"input","id":"s-in","label":"Qty CSRF-VIA-LABEL"}` |
| same, but bound to a secret path                                             | `"⟨secret⟩"`; mirror's own record correctly `secret:true` | `"label":"Qty PIN-VIA-LABEL"`                              |
| `<label>Current key: <span data-tosi-secret>sk-live-…</span><input></label>` | —                                                         | `"label":"Current key: sk-live-LABEL-WRAP-LEAK"`           |
| `<input aria-labelledby="ar-span">`, span bound to undeclared `arPriv.csrf`  | throws                                                    | `"label":"ARIA-SCOPE-TOKEN"`                               |
| `aria-describedby` on an `<h2>` (structural tier)                            | throws                                                    | `"description":"ARIA-SCOPE-TOKEN"`                         |

`<label>` associated with a form control is the most common naming idiom in real HTML — agent.ts:692's own comment says so, which makes it the highest-traffic of the three sources. A password `<input>` nested in a wrapping label does **not** leak (empty textContent); closed posture is safe.

**Fix:** one guard covering secrecy **and** scope, applied to all three label/description sources — not a copy of `referencedNodeIsSecret` into `associatedLabel`. Since `describeElement` is module-level and pure, thread a guard callback in rather than adding a fourth per-site restatement. Prefer withholding to truncating (a label is a name) and set `record.secret = true` when suppressing, so absence does not read as "this control has no label". Fixtures: `label[for]` × wrapping `<label>` × `aria-labelledby` × `aria-describedby`, each × {secret, out-of-scope} × manifest posture. The existing new test covers aria-\* × secret × `expose:'all'` only — one cell of twelve.

### B-2 — an element's `text` harvest publishes a bound DESCENDANT's out-of-scope or secret value

`src/agent.ts:1852` · **verified by execution** · security

`outOfScopeBinding` (agent.ts:1750) is built from `getElementBindings(el).dataBindings` — **this element only, no subtree arm exists**. `harvestWouldLeak` (agent.ts:1205) _does_ have a subtree arm, but it matches secret _controls_ and `data-tosi-secret` marks, never a plain `<span>` merely **bound** to a secret path. So the marked descendant is caught and the bound descendant is not — while agent.ts:1163's own docstring states the invariant as "a wired ancestor otherwise launders its descendant's text".

Manifest posture: an in-scope binding (or in-scope **handler**) on a wrapper makes it `wired`; a child bound to an undeclared path then rides out in the wrapper's text:
`{"tag":"div","id":"a-panel","text":"Session: DESC-TOKEN-LEAK"}` while `read('aPriv.token')` throws.

Under `expose: 'all'` the same shape defeats secrecy, and the payload is **self-contradictory in one response**: the mirror's own record is suppressed (`secret:true`, no text), the sibling password control redacts to `"⟷ zApp.pin"`, and the ancestor publishes `"text":"Pin: ANCESTOR-SECRET-LEAK"`. That internal inconsistency is what makes this a defect rather than a design position.

The scope guard is **new in this diff** (`d8c0790`) and element-local by construction. Requires only an ordinary nested layout with a bound child.

**Fix:** collect descendant binding paths once (`el.getElementsByClassName(BOUND_CLASS)` → the existing `bindingPathsOf`, which already fails closed) and feed the union — self + descendants — to **both** `outOfScopeBinding` and `harvestWouldLeak`. Fold the scope test _into_ `suppressHarvest` rather than leaving it a separate `!outOfScopeBinding` condition at each call site. Existing round-4/B-1 fixtures cannot fail here because every one of them binds the harvested element itself.

### B-3 — `agent-surface.md`'s highlighted callout states the exact opposite of the shipped invariant

`agent-surface.md:236-242` · **verified end to end** · docs / blast-radius

> "**`expose` scopes STATE, not the map.** … It does not narrow what `describe()` walks — the map covers the whole page in every mode: headings, landmarks, links and their `href`s, contenteditable text, labels, placeholders and geometry."

False in **both** production postures after this diff. `closed` gates the entire DOM walk (`agent.ts:1711`). Under a manifest, `scoped = !exposeAll` now gates the href tier (`:1904`), contenteditable (`:1925`) and self-declared components (`:1956`). Runtime probe on one page: `expose:'all'` → 4 records; `expose:{roots:['pApp']}` → 2 (link and contenteditable gone); closed → 0. The diff's own new test `a MANIFEST closes the DOM walk too` pins this.

It ships: `agent-surface.md` is `docPaths` entry 9 and the sentence is present in the committed `docs/agent-surface/index.html`. It self-contradicts six lines below (the tier ladder says the closed default has "no wiring"), and the CHANGELOG explicitly names **this page** as "the one that calls the manifest the production floor" — then leaves it unedited.

Two propagation paths, both bad: a security-conscious reader sizes their manifest from a false leak model (adding a root now also unlocks DOM harvests — the exact conflation that produced four leak rounds); and a consumer who _wanted_ a whole-page map silently gets a truncated one on `^1.8` → 1.9.0.

**Blast radius is wider than the finding states** — the same stale claim also sits in:

- `derived-surface.md:783` (`<a href>` … "mapped bindings-or-not") and `:784` (contenteditable … "mapped even before bindings attach")
- **`src/agent.ts:351-360`**, the TSDoc on `AgentWiringRecord.href` / `.contentEditable` — which ships as **`dist/agent.d.ts:230-237`**, i.e. it is in the published package and reaches consumers' editor tooltips
- `src/agent.ts:1907-1908`, an inline comment sitting directly above the `if (!scoped)` that makes it untrue

**Fix:** rewrite the callout to the shipped rule (under any allowlist an element earns a map place by being _declared_ — in-scope binding or in-scope handler — never by existing in the DOM; `describe({scope})` narrows further), fix the two derived-surface rows, fix the TSDoc, rebuild `docs/`. While there, note the resulting gap: under a manifest there is currently **no grant** for "links are fine" short of `expose:'all'`.
