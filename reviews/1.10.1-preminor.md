## Blockers

### B1 — correctness — `ElementPart` resolves to `any`, deleting all element-factory argument checking and breaking inline event-handler inference

`src/xin-types.ts:400` · committed artifact `dist/xin-types.d.ts:267`

The union gained `| BoxedProxy<any>`. `any` distributes through `BoxedProxy`'s conditional; the `T extends Function ? T & TosiProps<Function>` branch yields `any & …` = `any`; a union containing `any` **is** `any`. Confirmed by execution against the committed declarations — `0 extends (1 & ElementPart) ? true : false` compiles as `true`, and so therefore do `ElementCreator<T>`, `HTMLElementCreator`, `FragmentCreator` and every `Component.elementCreator()` return.

Two consequences, both reproduced with `tsc --strict` against `dist/index.d.ts`, both regressions against v1.10.0:

1. **Breaks compiling code.** `elements.button({ onClick: (evt) => evt.clientX })` → `error TS7006: Parameter 'evt' implicitly has an 'any' type`. The same file compiles clean against v1.10.0's declarations. This is the library's own dominant idiom (`src/component.ts:134`, `src/elements.ts:382`, `src/list-binding.ts:297-299`), and it fails in any `noImplicitAny` consumer.
2. **Silently accepts garbage.** `elements.div(() => {})` and `elements.div(new Date(), Symbol('x'))` now typecheck; at v1.10.0 both were `TS2345`. This is tosijs#36's defect (`[key: string]: any` making every typo compile) reproduced one layer up.

The motivating problem was real — `elements.div(app.name)` genuinely was `TS2345` at v1.10.0. The defect is the *choice of `any`* as the widening, not the widening.

**The new gate cannot see it.** `src/type-surface.test.ts:124-170` only asserts `errors: ''` — trivially satisfied once the parameter is `any`. The widening made to satisfy the gate is what blinds the gate.

**Fix (verified working in this review).** Replace `| BoxedProxy<any>` with `| BoxedScalar<any> | TosiProps<any>`. Compiled clean: accepts object, array and scalar proxies; `IsAny<ElementPart>` is `false`; `() => {}` is still rejected (`@ts-expect-error` satisfied). Regenerate `dist/`. Then give the gate a way to fail — add to `src/type-surface.test.ts` a negative probe expecting an error on `div(() => {})`, plus a handler-inference case (`button({ onClick: (evt) => evt.clientX })` must compile with no TS7006). A `tsc --noEmit` gate that only ever asserts success cannot detect a widened-to-`any` surface.

**Re-review scope:** correctness + blast radius over the remediation diff only (`src/xin-types.ts`, regenerated `dist/`, added gate assertions). Note the fix will likely change the 165-error test-file count (see gaps) — re-measure, do not assume.

## Majors (fix now, or file as scheduled follow-ups)

### M1 — correctness — the "put the committed bundles back" fix only runs on the first build; the watch rebuild deletes them again with no restore

`bin/site.ts:248`

The restore loop sits inside `buildLibrary()` under `if (!full)`, and `buildLibrary` is called exactly once, from module top level (`bin/site.ts:752`). The watch path never calls it — `rebuild` (`bin/site.ts:739`) is `buildSite(config)` + `buildDocsBundle()`. `buildSite`'s prebuild does an unconditional `rm -rf dist` (`node_modules/tosijs-ui/dist/doc-system/site/orchestrator.js:418`; the last-good stash covers `docs`, not `dist`), then with `libraryTsconfig` set only runs `tsc -p`, which emits per-file JS — no bundles.

So: `bun start`, save any watched file → **all 8 tracked bundles** (`module.debug.js`, `module.safe.js`, the five main/alt bundles, and `dist/cli.mjs`) are deleted, none rebuilt, none restored; the next `git add -A` commits the deletions. Git corroborates the recurrence the comment cites: `git log --diff-filter=D -- dist/module.debug.js dist/module.safe.js` → `5229813`, `47188a1` (the 1.10.0 release commit), `7dd02d1` (the 1.10.1 release commit).

`playwright.config.ts` does **not** set `DEV_NO_WATCH=1` for its `bun start` webServer, so a watcher is live for the whole browser lane too.

Blast radius is capped: `bin/check-publish-tag.ts` (wired as `prepublishOnly`) refuses to publish when any `exports` target is missing or untracked. The terminal outcome is a blocked publish plus a bad commit, not a shipped-broken package — but `dist/cli.mjs` is `bin`, not `exports`, and is covered by no gate at all. The comment's claim that the problem is "ended by not relying on remembering" is false: it still relies on remembering not to save a file while `bun start` runs, which is the ordinary dev loop.

**Fix:** extract as `restoreCommittedBundles()` and call it at the end of `rebuild` as well; widen it from `stage === 'tjs'` to any tracked `dist/*` the current run did not build. Add `DEV_NO_WATCH: '1'` to the Playwright webServer env.

## Completeness gaps

- **Diff basis is sound.** Tree clean, `v1.10.0` is the latest tag, `package.json` is 1.10.1, 50 files / 21 commits, committed build outputs correspond to HEAD. The four lenses reviewed the right thing.
- **No gate runs `tsc --declaration` — the exact failure mode of tosijs#38 is unprotected.** #38 was `--noEmit` clean and `--declaration` failing with TS2742 on 34 files; both new guards run `--noEmit`. The fix works (verified by emitting declarations for a downstream consumer), but nothing in the suite would catch a future unnameable inferred return type, which is 1.10.0 reproduced verbatim.
- **The downstream that reported #38 was never built against 1.10.1.** `/Users/tonioloewald/tosijs-ui` declares `^1.9.1` with 1.9.1 installed. The CHANGELOG's verification is a synthetic reproduction of tosijs-ui's component *shape*, not the 34-file `tsc --declaration` run the issue describes.
- **The new type-surface gate is one build behind, and silently skips.** The two dist-based tests are `test.skipIf(!existsSync('dist/index.d.ts'))`, and `buildLibrary()` runs `bun test src/` at `bin/site.ts:165` — **before** declarations are regenerated. On a release build they validate the *previously committed* `dist/*.d.ts`, so a newly-added-but-unexported type passes on the build that ships it and fails only on the next. On a checkout without `dist/` both vanish with a green tick — "a gate that cannot fail is worse than no gate", in a second form. **These are the two skipped-capable tests this report is required to name; they are not waved away — they are scheduled above and must be reordered or made unskippable.**
- **Only `dist/index.d.ts` is probed.** The release's thesis is that explicit export lists strand types, yet all three probes import from `dist/index`. `src/index-state.ts` (`tosijs/state`, its own explicit list), `src/index-core.ts` (`tosijs/core`) and `dist/index-agent.d.ts` (`tosijs/agent`, deliberately narrower) are exactly where a name goes missing, and none is imported by any test.
- **165 type errors remain in `src/*.test.ts` and nothing typechecks them.** Re-measured in this review: `tsconfig.json` still carries `"exclude": ["src/**/*.test.ts"]`, `package.json` has no `typecheck` script, `tsc -p tsconfig.json` is clean, and the same config including tests reports **165** errors across 15 files (`xin.test.ts` 53, `component.test.ts` 36, `form-validation.test.ts` 21, `list-methods.test.ts` 14, `bind.test.ts` 13). Three separate source comments in this diff name "invisible because no lane typechecks `*.test.ts`" as the cause of the bugs being fixed; `TODO.md:38` defers the lane and notes ~85 are the deliberate direct-assignment class. The remaining ~80 are unclassified, so it is unknown whether more type-narrower-than-runtime defects sit in them. **Note for the B1 remediation:** fixing `ElementPart` will change this count — re-measure after, do not assume.
- **`bun run test:browser` is unverified at HEAD, and the only changed browser test changed its own harness.** `tests/value-commit.pw.ts` moved off `goto('/')` onto a synthetic blank fixture to kill a Firefox flake — a sound change, but it re-hosts the lane's only real-engine value-commit regression test and was not re-run. Compounding it, the lane cannot be run without mutating committed `dist/` (M1), which is why this review did not run it.
- **Checked and clear — do not re-raise:** `bun test src/` 974 pass / 0 fail / 11.20s; `bun run format:check` clean; `bun run stamps --max-age 60` exits 0 (oldest claim 29 days). Two hypotheses actively refuted by experiment: widening `ElementPart` does **not** weaken excess-property checking on `ElementProps` (`div({classs:'x'})` already compiled clean at v1.10.0), and declaring `take`/`tosiBinding` on `TosiProps`/`BoxedScalarAPI` does **not** break state whose keys collide with those names.
