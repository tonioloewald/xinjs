## Blockers

### B1 — `Component.value` / `defaultValue` dropped from the public type surface; the interface merge the code claims does not exist

`src/component.ts:1424`, `:2723` · correctness + blast-radius · **verified, reproduced this session**

`src/component.ts:1424` reads `// (declared by interface merging below — see the note above)`, and a 27-line comment headed _"DECLARED BY MERGING, NOT AS CLASS FIELDS"_ sits above `class TosiSlot`. **No such interface exists** — `grep -rn 'interface Component\b' src/ dist/*.d.ts` returns only `ComponentMap`/`ComponentTrial`/`ComponentAttrs`/etc. Commit `591f035` says so itself: the merge was abandoned because `tjs convert` cannot parse it (_"Identifier Component has already been declared"_ — UPSTREAM.md tjs-lang#49). Both comments were left behind asserting a fix that was never written.

Reproduced against shipped `dist/index.d.ts` (tsc 5, `--strict`):

```
c.ts(4,18): error TS2339: Property 'value' does not exist on type 'Thing'.
c.ts(5,26): error TS2339: Property 'defaultValue' does not exist on type 'Thing'.
```

`git show v1.9.2:dist/component.d.ts:147` has `[key: string]: any`; HEAD has nothing in its place. `dist/component.d.ts:210-212` now ships the _"the component's value — a special property…"_ JSDoc orphaned directly above `_legacyTrackedAttrs?: Set<string>`, so the published types document a private tracking Set as the component's value.

The CHANGELOG says these members are _"now reached through a named `dynamic()` seam"_ — true inside the library, **false for every consumer**, because `dynamic` is module-private. Migration.md's 1.10.0 section and its _"What does NOT change"_ list never mention `value` at all.

**Blast radius is narrower than it first reads** (measured, not assumed): all 35+ tosijs-ui components that touch `this.value` already declare it, and the runtime already requires that (`initValue()` returns early with no own `value` descriptor and no `contract.value`). The genuine residual case is a class using `static contract = { value: … }` with no `value` field — it _does_ get a runtime accessor and now fails to compile. But the type surface of a release whose stated premise is _"tsc now tells you the truth about your own components"_ lies in the opposite direction about the property its own reference calls **the** special property, and the workaround is documented nowhere a consumer will see it.

**Fix.** Do **not** add `declare value: any` to the class without checking: a base property declaration makes `get value()` in a subclass **TS2611**, and a base accessor makes `value = ''` **TS2610** — both shapes exist in real components. Either (a) write the merge as an `interface` in a form `tjs convert` tolerates (a separate `.d.ts`-only declaration file is the obvious door), or (b) the honest docs-only minimum: **delete the two comment blocks that promise a merge that isn't there** (`component.ts:1398-1424`, `~2706-2723`), reattach the orphaned JSDoc, and add an explicit Migration.md item — _"`Component` no longer declares `value`/`defaultValue`; declare them in your own class (`value = ''`, `declare value: MyType`), as the docs' own `LabeledInput` example does"_ — citing tjs-lang#49.

### B2 — The private `dynamic()` helper leaked into the published component reference, including a **live** ```js example that throws

`src/component.ts:77,85,86,269,270` · correctness + blast-radius · **verified, reproduced**

The same global replace escaped the code and rewrote the `/*# … */` doc block. `git diff v1.9.2...HEAD -- src/component.ts` shows its **first three hunks are entirely inside the doc block**. `dynamic` is `const dynamic = …` at `component.ts:1098` — not exported from `component.ts`, absent from all 84 exports of `dist/module.js`.

- `src/component.ts:77,85,86` are inside a ` ```js ` fence → confirmed rendered as `<code class="language-js">` at `docs/component/index.html:99/111/119/120`, i.e. a **live example** the tosijs-ui runner executes.
- Reproduced the failure by running the published example text through the runner's own `new AsyncFunction(...contextKeys, code)` shape under happy-dom: `ReferenceError: dynamic is not defined at render (…component.ts:2541)`. It fires from the queued `render()`, so it escapes the harness's try/catch and surfaces as an **uncaught page error** — not a contained in-example message. The page shows the label with an empty input, and throws again on every keystroke.
- Shipped in: `docs/component/index.html` (5 hits), `docs/docs.json`, `docs/iife.js.map`, and `OEBPS/component.xhtml` inside `docs/tosijs.epub`. `docs/llms.txt` is clean (index only).
- The example class **already declares `value = ''`**, so plain `this.value` was correct there and needed no change at all.
- Same replace corrupted prose: `src/component.ts:1762` now reads _"…killing the handler before it committed `dynamic(this).value`."_ — a sentence about a _consumer's_ commit, pointing the next reader at an unrelated internal.

Nothing catches this: the Playwright lane harvests ` ```test ` fences only.

**Mitigation, worth stating:** `package.json` `files` publishes `dist/`, `LICENSE`, `README.md` — **the npm tarball is unaffected**. The damage is confined to the public doc site, the epub, and `docs.json` (the corpus both humans and LLMs read). It is still the flagship example on the highest-traffic reference page, and it teaches every reader to call an API that does not exist in the package.

**Fix.** Revert the five doc-block occurrences and line 1762 to `this.value`, rebuild `docs/` + epub, then `grep -r 'dynamic(this)' docs/` must return 0 before publishing.

## Major (non-blocking, but fix in the same pass)

### M1 — The documented "`withAttributes` and `static initAttributes` compose" path does not typecheck, and the non-spread form **silently drops the base's attributes at runtime**

`Migration.md:77`, `CHANGELOG.md:59`, `src/component.ts:400`, `CLAUDE.md:269` · correctness · **verified, both halves reproduced**

Four places tell users to build a base with `withAttributes`, extend it, add attributes with `static initAttributes` — _"they compose"_. Neither form works.

- **Without spreading:** `TS2417` (_"Property 'label' is missing in type '{ extra: number }'"_) **and** `TS2339` on `this.extra`. If both are silenced, the runtime probe prints `RESOLVED: {"extra":7}`, `observedAttributes: ["hidden","extra"]`, `label = undefined` — the base attribute is dropped from the map _and_ from `observedAttributes`, severing reflection in both directions, while `DeclaredAttributes` still types it `string`.
- **With spreading:** compiles and works at runtime, but `this.extra` is `TS2339` — reinstating exactly the untyped-attribute problem `withAttributes` was added to solve.

Cause is `_resolveInitAttributes()` at `src/component.ts:1322`: the no-contract path is a bare `return this.initAttributes`, so an own static shadows the parent's. **The contract path twelve lines above (1296-1312) already does the merge**, with a comment saying a subclass _"must not silently drop the base class's initAttributes … no throw, no warning"_ — the fix exists, applied only on the other branch.

The new test `src/component.test.ts:2415-2445` passes only because it reads through `as any` on both sides, so it pins neither failure.

_Scope:_ the runtime shadowing is pre-existing (`v1.9.2:src/component.ts:1191` is identical); what this release introduced is documentation newly recommending the pattern that hits it, plus both type errors.

**Fix.** Merge the inherited map on the plain path too (mirror the contract branch). Document the typed composition that actually works — spread **plus** `export interface Sub extends ComponentAttrs<typeof Sub.initAttributes> {}` (verified: typechecks clean, gives both `this.label` and `this.extra`). Update all four prose sites and drop the `as any` casts from the EXTENDED test.

### M2 — A types-only breaking release shipped with **no type-level artifact gate**

cross-cutting · blast-radius · **verified**

Every gate in `buildLibrary()` checks _values_: the unit suite, the per-bundle runtime smoke import, the DOM-free gate, gzip budgets. `grep -rln "tsc "` over `bin/`, `package.json` and `.github/` returns **zero** hits; there is no `typecheck` script and CI has only `bun test` + `playwright`. The only tsc run is buildSite's over `src/`, where the library's two in-repo components hand-declare their attributes and the only `this.value` uses are inside uncompiled doc blocks.

Result: the release whose _entire content_ is a type change shipped a missing `value` declaration and a broken doc example with 946 tests green. Checklist step 8c (_"install what you published and run it"_) structurally cannot catch it — running an artifact exercises values.

UPSTREAM.md already records _"execute/inspect the artifact, not the repo"_ as a lesson learned twice this quarter (tjs-lang `new`-stripping; tosijs-ui#127). This release re-hit the same class from the type side.

**Fix.** Add `type-tests/` compiled against the published declarations (`paths: { tosijs: ['dist/index.d.ts'] }`, `tsc --noEmit`) in `buildLibrary()` beside the smoke import. Ten lines covers it: a subclass using `this.value`, a `get value()` override, `handleResize() {}`, a `withAttributes` class asserting `this.count` is `number`, and a `// @ts-expect-error this.nope()` so the removal itself stays pinned.

## Minor / nit — all deferred to follow-ups (none block)

- **`ComponentClass<T>` and `DeclaredAttributes<A>` are not exported from `tosijs`** — _verified by me this session_ (was unverified): `import type { ComponentClass } from 'tosijs'` → `TS2305`. `ComponentClass` is now the declared type of the public `TosiComponentSpec.type` / `TosiPackagedComponent.type`, but `src/index-core-exports.ts:35` names only `PartsOf, ComponentAttrs`. CLAUDE.md warns about exactly this explicit-export-list trap. A blueprint author cannot name the type their own `type` field must satisfy.
- **Consumers of unmigrated component libraries go red on a `^` bump** — tosijs-ui 1.12.0 peers `tosijs ^1.7.8`, so npm resolves 1.10.0 in; `m.month = 5` on a `TosiMonth` → `TS2551`. But the one-line consumer fix exists and works (verified): `declare module 'tosijs-ui' { interface TosiMonth extends ComponentAttrs<typeof TosiMonth.initAttributes> {} }`. Migration.md has no _"you consume a library that hasn't migrated"_ section.
- **README's hand-written "Entry points" size table contradicts the generated block on the same page** — table says 36/24/16/26 KB; measured under the build's own basis 42/26/16/28 KB (the generated block at README.md:81-84 reproduces exactly). Understated ~6–14% on three of four rows. Pre-existing (`git diff v1.9.2...HEAD -- README.md` is empty) and already wrong when written. Live at `docs/index.html:77` and on npm. The line-3 metadata _"~27kB from a script tag"_ is a third number feeding `llms.txt`.
- **Stale hand-written agent-surface size claims ship to npm** — README.md:86-89 and CLAUDE.md:7 still carry _"6.7 kB gzipped … 10.6 kB … +2.9 kB (+13.7%) against 1.7.9"_, carried unactioned from `reviews/1.9.0-preminor-round2.md`. Measured now: `module.js` 42,178 B − `core.js` 25,844 B = 16,334 B vs the 15,285 B the claim was written for. One README paragraph mixes fresh generated numbers with stale hand-written ones.
- **`contractViolation()` fails open on a boolean validator** (`src/contract-check.ts:226`) — `verdict !== true` then `verdict.message`: a `false`-returning ajv-style validator yields `undefined`, and both call sites test `== null`, so `required`/`minimum`/`pattern` go silently unenforced _while `warnIfFailsOpen` is suppressed and `getContractValidator()` reports the engine installed_. A `null`/`undefined` verdict instead **throws out of the component `value` setter**, before assignment. TS rejects the misuse (`ContractValidator` is `=> true | Error`), and the degraded state equals the no-validator baseline — hence minor, not major. No malformed-verdict test exists.
- **`settings.blueprintSrcCheck` refuses only on exact `=== false`** (`src/blueprint-loader.ts:313`) — an `async` hook (a Promise is never `=== false`) or a hook missing its `return` **silently allows every src**, including one injected via unsanitized HTML, and `import()` executes it. Scheme refusal still holds, so not a full bypass. TS catches both mistakes; plain-JS/IIFE consumers are exposed.
- **(nit)** `madeComponents['__proto__'] = …` (`src/make-component.ts:163`) reassigns the map's prototype. Object-local, no privilege gained — hygiene. _(unverified)_
- **(nit)** `dynamic()` is a real runtime identity function, not an erased cast — 31 call sites, ~50 B gz, JIT-inlined after warmup. **Do not churn 31 sites for this alone**; fold in only when tjs-lang#49 lands. _(unverified)_
- **(nit)** Hand-written `declare` twins of `initAttributes` keys in `Blueprint`/`TosiSlot` can drift from the map they mirror. Keep-decision correctly recorded inline + in UPSTREAM.md. _(unverified)_
- **(unverified)** Live ```js doc examples are executed by no gate — the same hole that let B2 through, stated as a coverage gap rather than a defect.
