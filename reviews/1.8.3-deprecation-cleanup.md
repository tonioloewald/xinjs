## Per-lens summary

**Correctness** — The headline fix (tosijs#31, "stop the library warning its own users about API they never used") is genuinely half-landed. It fixed `listBinding()`'s two emission sites but missed `create()`, the most-used site, so the most idiomatic call form in the library still warns. Worse, the mechanism chosen for the fix — emitting the `bind` element-prop key — introduced a silent, order-dependent collision that can delete a list binding entirely. Net: the release trades a spurious console warning for a class of silent rendering failure.

**Security** — `agent.ts` is byte-identical to `v1.8.2` (`git diff v1.8.2...HEAD -- src/agent.ts` is empty), so both security findings are pre-existing 1.8.x defects rather than regressions. That changes triage framing, not the verdict: the path-level redaction guarantee is the agent surface's headline security property and it is broken in the default posture, through the only tool published in every posture. Shipping 1.8.3 re-publishes it.

**Efficiency** — No real efficiency defect survived verification. The one "hot path" claim was refuted on both legs (the caveat string is never built on that path; `ListBinding` clones templates and never re-enters `create()` on scroll). Two speculative micro-optimizations remain as unverified nits.

**Blast radius** — The strongest lens this round. It found that the sole regression guard for the release's headline fix is inert, that the library's public migration advice tells consumers to write props keys that do not exist, and that `.tosi.listBinding()`'s return shape changed observably with no changelog line.

## BLOCKERS

### B1 — `describe()` emits cleartext secret values that `read()` refuses

`src/agent.ts:900` (`boundValue`) · security · **CONFIRMED, re-reproduced during triage**

`boundValue()` redacts only on the _current element's_ `record.secret` flag. It never calls `isSecretPath()` / `containsSecret()` / `redactWithin()` the way `readScanned()` (agent.ts:1122-1128) does. The file's own comment at agent.ts:595 states the invariant it violates: _"SECRECY IS A PROPERTY OF THE PATH, not of a DOM record."_

Reproduced verbatim at HEAD — password input bound to `acc3.session.token`, button bound to the ancestor `acc3.session` with `bindings.enabled`, default `enableAgentInterface()`:

```
describe() → {"tag":"button","id":"go",
              "enabled":"{\"user\":\"ada\",\"token\":\"eyJhbGciOi.SECRET\"} ⟵ acc3.session"}
read('acc3.session') → {"user":"ada","token":"⟨secret⟩"}
```

The button's DOM is `<button id="go" class="-tosi-data">Go</button>` — the token appears nowhere on the page, so this is not "what the agent could already see."

Worse than originally reported: **no ancestor is required.** An element bound to the _exact_ secret path with a non-value binding also leaks, because `record.secret` is false for that element. Both `bindings.enabled` and `bindings.disabled` render nothing of the value to the DOM and idiomatically take object paths ("enable when session exists").

**Reachability is maximal.** `webmcpTools()` puts `tosi_describe` and `tosi_surface` in the unconditional base array; `tosi_read` / `tosi_changes` sit behind the `allowReads`/manifest gate _precisely because reads are considered too much to publish unasked_. So the read-only default hands a WebMCP host — and any third-party script on the page via `globalThis.tosiAgent` — the exact value `tosi_read` was withheld to protect. Also leaks in manifest mode whenever the secret's ancestor is a declared root (verified).

No test covers this: agent.test.ts:1367 (SEC-2) asserts read/changes/ancestor-read redaction only; agent.test.ts:1237 asserts only that the secret element's own record carries the flag.

**Fix:** route `boundValue()` through the same redaction as `readScanned()` — after `serialize(xin[path])`, if `isSecretPath(path)` return path-only (already done), else if `containsSecret(path)` run `redactWithin(path, raw)` before stringifying. Same for the unbound-control harvest and anywhere else `describe()` stringifies state. Add a test with a password-bound input plus an element bound with a named binding to the secret's parent path _and_ to the secret path itself.

**Re-review scope:** correctness + security over the remediation diff only (redaction helpers, the `describe()` walk, new tests). Confirm non-secret siblings still show and that provenance arrows / parsers are unchanged.

## MAJOR — fix before tagging

### M1 — `listBinding()`'s new `bind` key silently collides with a caller's own `bind:`

`src/xin.ts:1066` · correctness · **CONFIRMED, regression introduced by this diff, re-reproduced during triage**

`listBinding()` changed from `{ bindList: { value: path, ...options } }` to `{ bind: { value: path, binding: 'list', options } }`. `create()` (elements.ts:707-740) merges non-Element parts with `Object.assign(elementProps, item)` — two props objects carrying `bind` clobber each other, last write wins. Previously `bind` and `bindList` were distinct keys and both survived.

Reproduced at HEAD, both orders:

```
// caller bind first — the caller's binding vanishes, list renders
A: <div class="-tosi-data"><div class="virtual-list-padding"…></div>
     <div class="-tosi-data">x</div><div class="-tosi-data">y</div>…</div>
   (no data-title attribute — the caller's binding never ran)

// listBinding first — the LIST vanishes entirely
B: <div class="-tosi-data" data-title="hello">
     <template><div class="-tosi-data"></div></template></div>
   (template never consumed, zero rows)
```

Silent in both directions: no throw, no warning. The pattern — a container that is both list-bound and carries its own binding (empty-state class, aria-label) — is ordinary composition. tosijs-ui's two `data-table` call sites happen to pass no `bind` key, so they escape by luck, not design. No test in `src/*.test.ts` combines a container `bind:` with `listBinding()`.

**Fix (minimum for this release):** detect the collision in `create()` and throw or warn loudly rather than silently dropping one. **Fix (right):** make `bind` composable — accumulate a second `bind` into an array, widen `ElementProps.bind` (xin-types.ts:303) to `TosiInlineBinding | TosiInlineBinding[]`, and have `elementSet`'s `bind` branch iterate. Either way pin **both argument orders** in tests; the reverse-order case (total silent list death) is the one that matters.

### M2 — The headline fix misses its most-used site: `create()` still stamps `bindText`

`src/elements.ts:731` · correctness · **CONFIRMED, re-reproduced during triage**
_(merged: an efficiency-lens report of the same line — its performance claims were refuted, see below)_

```ts
} else if (tosiPath(item)) {
  elt.append(elements.span({ bindText: item }))
```

Unchanged by this diff. Pure current API, no deprecated key written by the user:

```
elements.div(w.name)  →  WARN: "bindText is deprecated. Use { textContent: ... } instead."
```

This is verbatim cause #1 of tosijs#31, and the commit fixed only the `listBinding` instance. Blast radius is the docs themselves:

- `src/list-binding.ts:28` — the **first live ```js example on the list-binding page** — is `ul(...arr.tosi.listBinding(({li}, item) => li(item)))`. Every visitor to tosijs.net/list-binding gets the warning.
- `src/elements.ts:76-95` — the **elements page's headline live example** — uses bare-proxy children twice (`div(elementCreatorDemo.clicks, ' clicks so far')`). Also warns. The commit's claim "all fences are now clean" is not true.
- The diff _added_ four more static snippets teaching this exact form (`src/list-binding.ts:227, 642, 761, 981`).

**Fix:** `elements.span({ bind: { value: item, binding: 'text' } })` — verified byte-identical output, no warning. Extend the tosijs#31 guard to cover `elements.div(proxy)` and `listBinding(({li}, item) => li(item))`.

_Refuted sub-claims from the efficiency lens, recorded so nobody re-litigates them:_ the 3-segment `caveat` concat does **not** run on this path (it is guarded on `typeof value === 'string'`; `create()` only reaches this branch when `item` is a proxy), and there is **no** per-scroll-pass cost (`ListBinding` builds stamp templates once and clones via `cloneWithBindings`; scroll never re-enters `create()`). ### M3 — The deprecation advice tells consumers to write props keys that do not exist

`src/elements.ts:658, 673` · correctness · **CONFIRMED**
_(merged: two lens reports of the same `alt`-table / caveat defect)_

The `alt` table stores replacement _fragments_ interpolated into `` `Use { ${alt}: ... } instead.` ``, but two of four entries are not props keys. Actual output, captured from a `bun test` run of this repo:

```
bindList is deprecated. Use { .tosi.listBinding(): ... } instead.

bindEnabled is deprecated. Use { disabled (with .tosi.take(v => !v)): ... } instead.
  Since you passed a PATH STRING, use { bind: { value: 'w.flag', binding: 'enabled' } } —
  { disabled (with .tosi.take(v => !v)): 'w.flag' } would set literal text, not bind.
```

Verified consequences: `div({ '.tosi.listBinding()': 'w.items' })` produces a junk attribute and no binding — the correct migration is a _spread_ (`...arr.tosi.listBinding(fn, opts)`), which the message never states. And `button({ disabled: 'w.flag' })` yields `<button disabled="">` — a truthy string that **permanently disables the control**, the opposite of what `bindEnabled` meant, and not "literal text" as the new caveat claims. A user following the message literally ships a dead button.

This diff _edited these exact lines_ (appending `${caveat}`) and left the two malformed entries, then re-interpolated them into the new caveat — so part of the wrong text is newly introduced. Nothing pins the message: `grep "is deprecated. Use {" src/*.test.ts` is empty. The `bindList` form prints during `bun test` today (visible in the run above) and from tosijs-ui's shipped bundles into downstream consoles.

**Fix:** make the table carry the whole replacement _sentence_ rather than a `{ key: … }` fragment, and drop the `Use { X: ... }` wrapper for `list`/`enabled`. Branch the caveat on binding type so the `disabled` family says "would set the property to the literal string (always truthy)".

### M4 — Secret-path matching is spelling-sensitive: secrets inside lists leak in cleartext

`src/agent.ts:734` · security · **CONFIRMED** _(pre-existing — `agent.ts` unchanged since v1.8.2)_

A password/API-key field inside a list template binds to a bracket path. Reproduced against a real list binding with `{ idPath: 'id' }`:

```
read('acct.list[id=a1].pw') → '⟨secret⟩'    (correct)
read('acct.list[0].pw')     → 'hunter2'     (index-form alias)
read('acct.list.0.pw')      → 'hunter2'     (dot-index alias)
read('acct.list')           → [{id:'a1', label:'work', pw:'hunter2'}, …]
read('acct')                → {list:[… pw:'hunter2' …]}
changes(0) after any touch  → [{path:'acct.list', value:[… pw:'hunter2' …]}]
when('acct.list', …)        → [… pw:'hunter2' …]
```

The mirror case (no `idPath`) leaks the id-form instead. Two causes: (1) `redactWithin()` builds child paths as `` `${path}.${key}` ``, so descending an array yields `acct.list.0`, which `extendsPath` matches against neither spelling — recursion stops and the item is returned raw, _while the outer call believes it redacted_; (2) `isSecretPath`/`containsSecret` compare path **strings**, but id-form, index-form and dot-index all resolve to the same value — and `touch()` itself synthesizes id-path touches from index paths, so both spellings genuinely circulate.

`tosi_changes` is published on any scoped (`expose: { roots }`) surface and is the turn drain an agent calls every turn, so a scoped production manifest containing a list of cards or keys hands the secrets over on the next list mutation. SEC-2 (agent.test.ts:1367) asserts exactly this property for a plain nested object and passes; the bracket case has no test.

**Fix:** make secrecy matching spelling-independent. Minimum: emit `` `${path}[${i}]` `` for array indices in `redactWithin()`, and canonicalize both stored secret paths and the queried path before comparison. Belt-and-braces: once an array item is known to contain a secret leaf, redact that leaf **by key** across sibling items. Test all three spellings on item / array / root, plus a `changes()` drain.

### M5 — The regression guard for this release's headline fix passes vacuously

`src/xin.test.ts:1902` · blast-radius · **CONFIRMED by injected-regression experiment**

`warnDeprecated(key, msg)` (metadata.ts:161) latches once per key in a module-level Set shared across the whole `bun test` process. `src/xin.test.ts` executes `bindText:` at lines 1155, 1593, 1636 and 1665 — all before the guard at 1902 — so key `bindtext` is already latched when the guard installs its `console.warn` spy. It asserts `[]` against a muted channel.

Decisive experiment: reverting `listBinding()`'s default content to `span({ bindText: '^' })` — _the exact regression the test's own comment names_ — leaves `bun test src/xin.test.ts` at 115 pass / 0 fail, and the full suite byte-identical to baseline. The regression is invisible to the entire suite. Run in isolation (fresh latch state) the same test correctly fails, confirming it is inert rather than wrong.

Stronger than reported: the guard contributes **no** unique coverage on either axis. Injecting the `bindList` half of the regression also leaves the guard passing; only three unrelated shape assertions (xin.test.ts:1141, 1159, and "tosiListBinding method on boxed arrays") catch it.

**Fix (validated):** call the already-exported `_resetDeprecationWarnings()` (metadata.ts:172 — component.test.ts:877/896 sets the precedent) at the top of the guard. With that, the injected regression fails the file run (114 pass / 1 fail). Add a positive control in the same test (deliberately trip one warning, assert exactly one) so the test proves the channel was live.
