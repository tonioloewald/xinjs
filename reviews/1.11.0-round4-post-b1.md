## Blockers (fix before tag)

### B-1 — Containment-derived `record.secret` is fed to `addSecretPath()`: one `describe()` permanently marks ordinary state paths secret
`src/agent.ts:1544-1548`, consumed at `:2153` and `:2159` · **verified twice, independently (correctness + security lenses)**

`describeElement` now does `const secretHere = referencedNodeIsSecret(el); if (secretHere) record.secret = true` **before** `recordFor`'s data-binding loop. `referencedNodeIsSecret`'s second arm is `deepHas(el, SECRET_CONTROL_SELECTOR)` — *"contains a secret control anywhere below, shadow trees included"*. But `recordFor:2153` reads that same flag as an **identity** signal (`if (record.secret === true) addSecretPath(b.path)`), written when it could only mean "this element **is** a secret control". `secretPaths` is module-level and append-only for the session.

Reproduced on HEAD and shown **absent at `e29b44a`**:
- `<div>` with a toDOM-only binding to `pe.theme`, containing an `<input type="password">` → `read('pe.theme')` is `dark` before `describe()`, `⟨secret⟩` after, and `read('pe')` → `{theme:'⟨secret⟩'}`. Stays `⟨secret⟩` after the password field is removed from the DOM, after `disable()`, and across a fresh `enableAgentInterface()`.
- A `<form>` bound to `pf.theme` whose only "secret" descendant is `<input type="hidden" name="csrf">` — an ordinary CSRF token — same result.

The repo's own regression test for this failure, `src/agent.test.ts:2954` (*"a hidden input in a component does not redact the host binding"*), **fails if you insert one `agent.describe()` before the read**. It is green only because it reads without describing. `refreshSecretPaths`' comment at `:1266-1277` documents this exact shape as *"a silent, permanent availability break of the surface this release exists to harden"* and narrows its shadow-host arm with `fromDOM != null`; the new arm bypasses that narrowing entirely, including for toDOM-only bindings. The commit's own comment at `:1538-1541` claims to avoid *"the over-redaction failure of 1.10.0, where one password field marked a whole state root secret"* — it avoids it on the scope arm and reintroduces it on the secrecy arm.

Fail-closed (never a leak), but `describe()` is the unconditionally-registered `tosi_describe` and the first call in the documented flow, and it poisons paths *after* the `inScope` test — i.e. exactly the paths you chose to expose.

**Fix:** keep `secretHere` for what B1 needed (suppressing `href`/`placeholder`/`title`/`alt`/`checked` on the record) but do **not** assign it to `record.secret`. Make the path escalation at `:2153` and the `boundValue` argument at `:2159` ask an element-local question: `isSecretControl(el) || closestAcrossRoots(el, '[data-tosi-secret]') != null`. Containment must never imply "the paths bound *here* are secret".

**Pin with:** the `agent.test.ts:2954` fixture plus a `describe()` before the read; a light-DOM bound container wrapping a password field; the same wrapping a `type="hidden"` input; a shadow-host toDOM-only binding.

**Re-review scope:** correctness + blast-radius over the remediation diff; security re-runs the four B1 token substrings to confirm the narrowing did not re-open the attribute leak.

### B-2 — `aria-description` is the fifth free-text attribute in the same harvest and was never gated
`src/agent.ts:1605-1608` · **verified twice, independently (security + blast-radius lenses)**

```ts
const description =
  referencedText(el, 'aria-describedby', withheld) ||
  el.getAttribute('aria-description')     // ← unguarded
```

The B1 fix enumerated and gated `title`/`alt`, `placeholder`, `href` and `checked` on `secretHere`. The `aria-describedby` arm is guarded (via `referencedText`); the raw-attribute arm eight lines below the fix is not, so the two arms of the same field disagree.

Reproduced on HEAD under the MANIFEST posture: `<input data-tosi-secret aria-label="One-time code" aria-description="OTP-987654" bindValue=…>` emits `{tag:'input', secret:true, label:'One-time code', description:'OTP-987654', value:'⟷ mf.name'}` while `read('mf.name')` returns `⟨secret⟩` — the self-contradicting record B1 was filed for, verbatim. It fires on the structural tier too (`<h2 data-tosi-secret aria-description="…">`). Verified present in `dist/module.js` and `dist/main.js`.

Two extras the verifiers found beyond the original claim:
- **`referencedText()` only asks `referencedNodeIsSecret` about the *target*, never about `el`** (`src/agent.ts:784`), so a `data-tosi-secret` input with `aria-describedby` pointing at an unmarked node also publishes cleartext. The whole description channel bypasses `secretHere`, not just one spelling.
- The codebase's own taxonomy settles the "is a description a name?" question against the current code: `src/agent.ts:235` — *"a description is NOT a name"* — and the fix's rule is *"A NAME SURVIVES SECRECY, CONTENT DOES NOT"*.

Reachability is the same argument the CHANGELOG uses to classify B1 as security: `src/webmcp.ts:106` pushes `tosi_describe` into the unconditional base tool array; `canRead` at `:138` gates only `tosi_read`/`tosi_changes`. The value the read gate withholds is handed to the model-context host.

The new tests cannot catch it: the substring-over-the-whole-map assertion is the right shape, but the fixture enumerates only four tokens (href ×2, placeholder, title). `aria-description` is outside the *fixture*, not outside the *assertion*.

**Fix:** `(secretHere ? null : el.getAttribute('aria-description'))`, and pass `el`'s own secrecy into `referencedText` so the referenced arm is covered too. Add `aria-description` (both spellings) to the token list in `describe(): secrecy covers the ATTRIBUTE harvest`, and add the mirror case to the over-redaction control.

**Structural recommendation (this is the eighth address of the invariant, and per-site restatement has missed a site in each of the last three rounds):** replace the enumeration with a single list of `(attribute → record field)` pairs read behind one guard.

## Major (verified) — fix now or file with the cost stated

### M-1 — `describe()` is 45–55% slower in real Chromium, paid on every page with zero secret controls
`src/agent.ts:1544` · **verified independently, with its own harness**

The single new line `const secretHere = referencedNodeIsSecret(el)` is unconditional in `describeElement`, and its second arm (`deepHas`) issues **two** queries per call — the 15-arm secret selector and `querySelectorAll('*')` over the whole subtree to find shadow roots. `describeElement` runs for every wired element (`:2100`) and every structural element (`:2483`). Pre-existing guards in the structural tier were behind `heading && …`, so `main`/`section`/`article`/`nav`/`header`/`footer` and every ancestor custom element went from **zero** subtree scans to a full one — and those are the largest subtrees.

Real Chromium, median of 9 after 3 warm-ups, `dist/module.js` at `e29b44a` vs HEAD, **no secret controls anywhere**:

| elements | e29b44a | HEAD | delta |
| --- | --- | --- | --- |
| 1,219 | 4.2 ms | 6.1 ms | +45% |
| 3,649 | 13.2 ms | 19.8 ms | +50% |
| 10,939 | 41.5 ms | 64.4 ms | +55% (+22.9 ms blocking) |

`wiring.length` is identical at every size — pure overhead, no output difference. Instrumented under happy-dom: exactly +2 `querySelectorAll` per `describeElement`, and nodes materialised blow up 4.4× → 8.5× with nesting depth. `agent.ts:1205` already records that happy-dom memoises `querySelectorAll` and real engines do not, so this is a floor.

`tosi_describe` is the one WebMCP tool registered unconditionally — a model calls it every turn. The ~40-line CHANGELOG entry states no performance consequence, the same omission this review round raised about `auditView`.

**Fix (cheap, and it also removes an over-redaction):** the subtree arm is inert at this call site — none of `href`, `placeholder`, `title`/`alt`, `checked` is made secret by a *descendant*, and `checked` only reads on `<input>`, which is void. `isSecretControl(el) || closestAcrossRoots(el, '[data-tosi-secret]') != null` keeps both real arms at O(depth). **This is the same narrowing B-1 requires**, so one change closes both. If subtree semantics are wanted deliberately, hoist instead: `refreshSecretPaths` already runs `deepQueryAll(document, SECRET_CONTROL_SELECTOR)` once per `describe()` (`:2048`) — test containment against that set; with zero secret controls the arm collapses to a length check, and nothing is remembered across calls so the `:1176` "NO CACHE HERE" invalidation argument stands. `TODO.md:499` already specs this hoist (for `harvestWouldLeak`) and `TODO.md:1107` already records that `describe()` has no benchmark or budget; neither was updated by this diff.

Either way, **state the measured cost in the CHANGELOG entry beside the fix.**
