## Blockers (fix before tag)

### B1 — `[data-tosi-secret]` on a shadow host still leaks in cleartext

`src/agent.ts:806` · correctness · **CONFIRMED (reproduced 3×, with a clean control)**

`deepQueryAll(root, sel)` collects `root.querySelectorAll(sel)` and recurses into _descendants'_ shadow roots, but never inspects `root`'s **own** `shadowRoot`. `refreshSecretPaths` builds `const bound = [el, ...deepQueryAll(el, '*')]`, so when the marker sits on the shadow host itself — `<my-thing data-tosi-secret>`, the most natural place to put it — the subtree looks empty and nothing is marked. `agent.read('p4.token')` returns `"sekrit"`; the ancestor read and `agent.changes()` leak too. A real `Component` with `shadowStyleSpec` created as `<cred-box data-tosi-secret>` returns `"sk-live-123"`.

The shipped test passes only because its marker is on a plain wrapper _containing_ the host. `agent.ts`'s own new doc block states the guarantee unconditionally.

The DRY signal that predicted it: `deepHas` (819) hand-codes the own-shadowRoot check `deepQueryAll` omits — two near-duplicate walkers written in the same commit, disagreeing about the same question.

**Fix:** add the own-shadow-root arm to `deepQueryAll` (guarded for Document/ShadowRoot roots), delete `deepHas`'s duplicated arm so there is one walker. Add a unit test with the marker **on** the host, mirrored in `tests/shadow-secret.pw.ts`. _Re-review scope: correctness + security over the remediation diff; the change widens what is marked secret, so re-check it does not compound M1._

### B2 — `initAttributes` inheritance survives exactly one level, and the new docs steer into the break

`src/component.ts:1372` · correctness · **CONFIRMED (reproduced on both branches)**

`class A extends withAttributes({a:'a'}) {}` → `class B extends A { static initAttributes = {b:'b'} }` → `class C extends B {}` (adds nothing — the commonest kind of subclass). `C._resolveInitAttributes()` = `{b:'b'}`; `'a'` is gone, `C.observedAttributes` = `['hidden','b']`, `el.a === undefined`. Silent — no throw, no warning, reflection severed both directions, which is verbatim the defect this release fixes. Same via the contract branch: a plain subclass of a contract-bearing base loses the contract's attributes.

Both branches gate on an **own**-property check and then fall through to `return this.initAttributes` — a static prototype-chain lookup for the _raw_ value, never a recursive call to the nearest ancestor's _resolved_ map.

Two corrections to the original framing, neither changing the verdict: the contract half pre-dates this diff, and the old spread form still works. What **is** this diff's doing is the new instruction in `Migration.md` and the `component.ts` doc block — _"declare ONLY what you add… tosijs merges the whole prototype chain for you"_ — a general promise that is false one level down.

The two new tests only cover chains where **every** level declares something.

**Fix:** when `ownInit == null`, delegate up (`Object.getPrototypeOf(this)?._resolveInitAttributes?.()`, terminating at the Component/HTMLElement boundary) rather than reading the static. Add a non-declaring leaf to the three-level test, and a plain subclass of a contract-bearing base. _Re-review scope: correctness + blast-radius; `_resolveInitAttributes` feeds `observedAttributes`, `_describedAttributes` and three hydration call sites (component.ts:1935, 2022, 2449) — re-run the component and agent suites._

## Majors (do not block the tag; file and schedule)

### M1 — The shadow-host harvest permanently redacts the whole state root

`src/agent.ts:1243` · correctness + security (two findings deduped) · **CONFIRMED by execution**

The new walk pushes **every** shadow host up the chain (`node = host` and repeat, not one step) and harvests **all** of each host's `dataBindings` (not just the value binding). Consequences, all reproduced with a real `Component` in shadow DOM (the default):

- `LoginForm` with a password field in its shadow, host bound `bind(host, 'creds', …)` — the pattern `bind.ts`'s own warning tells you to use — makes `read('creds')`, `read('creds.user')` and `read('creds.theme')` **all** return `⟨secret⟩`.
- A bound app shell `<my-app>` containing one password field anywhere below marks `app` itself secret; the whole surface answers `⟨secret⟩`.
- `input[type="hidden"]` is in `SECRET_CONTROL_SELECTOR`, so a component with an internal hidden input triggers the cascade with no secret involved.
- `secretPaths` / `secretAncestors` are module-level and append-only — nothing clears them. After `host.remove()` + `updates()`, and across `disable()`/re-enable, reads still return `⟨secret⟩` for the page's lifetime.
- The identical markup in light DOM redacts only the password, so redaction now depends on whether a component uses shadow DOM.

The in-code comment at 1238-1240 states exactly the hazard the loop then commits. It also defeats the property this release's own `tests/shadow-secret.pw.ts` asserts ("redaction, not blanket refusal") as soon as any composing wrapper is bound — that test passes only because its host carries no binding.

Fail-closed, so not a leak: a silent, permanent **availability** break of the surface this release exists to harden.

**Fix:** stop at the **first** shadow host, and harvest only bindings that can carry the control's value (`binding.fromDOM != null`; a `toDOM`-only `text`/`enabled`/`class`/`list` binding cannot be where a typed secret lands). Keep the breadth-first subtree harvest for explicit `[data-tosi-secret]` regions, where breadth is the author's stated intent. Regression test: composed outer bound host + inner password, asserting non-secret siblings still read in cleartext. Consider making `secretPaths` per-surface (cleared on `enableAgentInterface`) now that the rule is wider.

### M2 — Every agent verb got 2–4.5× slower, and the source now ships a stale measurement

`src/agent.ts:806`, `:819`, `:1205` · efficiency + security + blast-radius (three findings deduped) · **CONFIRMED, independently re-measured in Chromium**

`refreshSecretPaths` now calls `deepQueryAll(document, …)`, which adds `Array.from(document.querySelectorAll('*'))` plus a `.shadowRoot` read per element — **unconditionally**, even on a page with zero shadow roots. It runs on every `read` (1960), enable (1966), `describe` (1981), `when` (2680) and `changes` (2745). `deepHas` replaced a single native `querySelector` at three sites, adding a full `querySelectorAll('*')` of the subtree on the common no-match path; `describe()` calls it per described element.

Measured (committed `dist/module.js` at `145250a` vs HEAD, alternated runs, headless Chromium):

```
1603 el /  20 hosts: read 0.182 -> 0.351 ms (1.9x) | describe 2.25 -> 2.77 ms (1.2x)
2323 el / 400 hosts: read 0.132 -> 0.779 ms (5.9x) | describe 1.34 -> 2.21 ms (1.7x)
4803 el / 400 hosts: read 0.423 -> 1.322 ms (3.1x) | describe 4.81 -> 6.51 ms (1.4x)
1623 el /   0 hosts: read 0.193 -> 0.343 ms (1.8x) | describe 0.99 -> 1.18 ms (1.2x)
```

The last row has **no shadow DOM at all** and still pays 1.8× — the finding understated this. In the module's own units, a 200-`tosi_read` WebMCP turn on a 4.8k-element page goes from ~85 ms to ~264 ms of synchronous main-thread blocking, and the caller controlling the call count is the model.

Two stale comments now ship: the measurement block at `agent.ts:1187-1203` ("~350µs at 2k, 1–2ms at 7k") is untouched and understates by ~2×, in the one comment written specifically to stop stale numbers shipping; and `:1451-1455` still boasts "ONE query… one less subtree scan per described element" directly above a call that now does two traversals. `TODO.md:94-98` (the hoist item) got only Prettier reflow and its premise is now invalid. happy-dom memoises `querySelectorAll`, so all 964 unit tests are blind to this.

**Fix:** keep the security fix, make the traversal cheap — (a) query `'*'` once inside `deepQueryAll` and derive both uses (free 2×); (b) a global no-shadow-host fast path restoring the exact 1.9.2 queries when no open shadow root exists; (c) short-circuiting `deepSome` instead of materialising every match in `deepHas`; (d) enumerate hosts once per pass and share, rather than re-walking per element. Better still, register shadow roots from `bind.ts` (which already crosses every boundary that matters) instead of discovering them by enumeration. Then **rewrite** both comments with fresh Chromium numbers — not as a diff against the old survey — and update the TODO item.
