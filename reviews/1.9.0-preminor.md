## BLOCKERS (3)

### B-1 — The `closed` default is not closed: `describe()` still publishes link targets, contenteditable live text, self-declared components, and page structure

`src/agent.ts:1697, 1715, 1743, 1838` (walks at `:1812`, `:1823`) · lenses: correctness + security (deduped — two independent lenses reached this by execution) · **verified/confirmed**

`enableAgentInterface()` with no arguments prints _"tosijs agent: nothing is exposed. describe() reports an empty app…"_, returns `exposure:'closed'`, `roots:{}`, `actions:[]` — and then returns non-empty `wiring`:

- `{tag:'a', href:'/admin/reset-token?u=ada', text:'admin reset'}` — tokens in query strings.
- `{tag:'div', contentEditable:true, text:'draft: my SSN is 123-45-6789', value:'…'}` — live user-typed draft, verbatim.
- `{tag:'priv-widget', description:'internal admin panel — kill switch', component:{actions:{wipe:{}}, attributes:{adminToken:{type:'string', default:'abc-123'}}}}` — private action namespace _and_ an attribute default value.
- `{tag:'h1', structural:true, text:'Acme Payroll — Q3 salaries'}` — suppressed in happy-dom **only** by zero-size rects; stubbing `getBoundingClientRect` (i.e. any real browser) publishes it.

Cause: of the five ways `wired` can be set, only two consult posture. Data bindings (`:1604`, `inScope`) and event handlers (`:1663`, `!scoped ||`) are gated; `a[href]` (`:1697`), `contentEditable` (`:1715`), `record.component != null` (`:1743`) and the structural tier (`:1838`) are gated on nothing. `closed` (`:1365`) is computed but used only for the console notice, the verb refusals and the `exposure` string — never in the DOM walk.

**The internal contradiction is the tell.** Ten lines from the contenteditable harvest, the unbound-form-control harvest _is_ gated `!scoped`, with the comment _"an allowlist that hides `read('app.pin')` must not hand the same digits over as DOM content"_. So an undeclared `<textarea>`'s value is correctly withheld while an undeclared `contenteditable`'s identical content is published. Same invariant, opposite answers.

**Delivery vector.** `tosi_describe` and `tosi_surface` are in the unconditional `tools` array (`src/webmcp.ts:101-124`), constructed _before_ the `canRead = exposure !== 'closed'` gate at `:135` and `canAct` at `:167`. `webmcp` defaults true (`agent.ts:1298`), `global` defaults true (`:2163`). A bare enable hands this to a model-context host — a different principal, typically off-device (the threat model stated at `agent.ts:74-79`).

**The guard test cannot fail.** `src/agent.test.ts:948/969` asserts `describe().wiring` is `[]` against a fixture of exactly one bound `<input>` — the one path that _is_ correctly gated. No `<a>`, no contenteditable, no self-declaring component, no heading.

**The claim is asserted and false in five places:** `agent.ts:33`, `agent.ts:43-44`, `agent.ts:1388` (runtime `console.info`), `CHANGELOG.md:29`, `src/docs/agent-surface.md`, plus the `AgentInterfaceOptions.expose` JSDoc that regenerates into `dist/agent.d.ts` and lands in consumer tooltips.

**Fix — pick one rule and make code and docs agree.**

- _Preferred:_ gate the four unconditional `wired = true` sites and the two dedicated sweeps on `scoped`, exactly as the same commit did for the unbound-form-control harvest. At minimum gate the **content** harvests (contenteditable text/value, heading text) — live text is content, not structure.
- _Or:_ if "DOM structure is always published, only STATE is scoped" is the intent, rewrite all five claim sites to say what `closed` actually withholds and what it still maps.
- Either way: extend the `:948` fixture to contain an `<a href>` with a token, a `contenteditable` with distinctive text, a heading, and a `static contract` + `static initAttributes` component, and assert the chosen contract.

_Re-review scope:_ correctness + security over the remediation diff. If the walk is narrowed, blast radius must cover `manifest`/`all` postures and downstream `describe().wiring` consumers (haltija, tosijs-ui, and this repo's own `auditAccessibility` / schematic renderer). If documentation-only, Tier 0 plus a correctness re-read of the five claim sites.

### B-2 — The structural tier is a fourth unguarded harvest: it defeats manifest scope, secret redaction, **and** `aria-hidden`

`src/agent.ts:1851-1872` · lens: security · **verified/confirmed** (worse than reported)

`recordFor()` does `seen.delete(el); return undefined` when `wired` is false (`:1777`, comment: _"release the claim; the structural tier may want it"_). The structural loop then re-visits that element and harvests `textContent` with **no** `inScope()`, **no** `harvestWouldLeak()`, and **no** `ariaHidden()` check — the last two being exactly the guards the round-4 fix added to `recordFor`'s other harvests (`:1668`, `:1707`, `:1560`).

Reproduced by execution (bounds mocked; no mock needed in a real browser):

- **(a) Scope bypass.** `expose: { roots: ['pub'] }`, an `<h2>` bound to `priv.apiKey`. `read('priv.apiKey')` throws _"is not exposed (manifest mode)"_; `describe()` emits `{tag:'h2', structural:true, text:'sk-live-DEADBEEF'}`.
- **(b) Secret bypass.** `expose:'all'`, `<h2>Recovery code: <span data-tosi-secret>ZX9-KK21</span></h2>` emits `text:'Recovery code: ZX9-KK21'`. The author's own opt-in, laundered through a heading. `record.secret === true` on an `<h2 data-tosi-secret>` is computed and then ignored.
- **(c) aria-hidden.** `<h2 aria-hidden="true">` is published with its text.
- **(d) Worse than reported:** with the bare 1.9.0 default, the same path emits `{tag:'h2', structural:true, text:'sk-CLOSED-9999'}` — the bound secret of a root the surface declares nothing about — while the console prints "describe() reports an empty app".

This is a distinct address from B-1 (it survives _any_ posture, including a correctly-narrowed one) and it directly falsifies `CHANGELOG.md:30`, _"the elements bound to it never appear in `wiring`"_.

_In fairness:_ only headings get `textContent`. Landmarks and custom-element ancestors (`:1845-1848`) get `describeElement()` fields only — real but lower-value.

**Fix:** route the structural harvest through `recordFor`'s guards — skip `ariaHidden(el)`; skip the text harvest when `record.secret === true` or `harvestWouldLeak(el, record, boundPaths)`; under `scoped`, refuse to harvest text from an element carrying bindings none of which are `inScope` (`getElementBindings(el)` already has this). Add regression tests for (i) an out-of-scope-bound `<h2>` under a manifest and (ii) a heading containing `[data-tosi-secret]` — no current test puts a bound or secret-bearing element in the structural tier, and every structural test must mock `getBoundingClientRect` or it silently tests nothing.

_Re-review scope:_ security + correctness over the remediation diff, **and re-walk every `describe()` text/value harvest for a fifth address** — there are now four known.

### M-2 — `Migration.md` has no 1.9.0 section, so the page whose job is announcing breaks omits the release's breaking change

`Migration.md` (headings: only 1.8.0 and 1.7.0) · lens: blast-radius · **verified/confirmed**

`git diff v1.8.2...HEAD -- Migration.md` is empty. It is `docPaths` entry 4 (`tosijs-site.config.ts:71`), rendered to `docs/Migration/index.html` — which was regenerated this release and contains **zero** occurrences of "1.9.0". Its meta description enumerates the covered releases, so a 1.9.0 reader is affirmatively told 1.9.0 is not among them. The only agent-posture statement on the page is `:51`, _"defaults to **read-only** introspection"_ — historically scoped under the 1.8.0 heading, but the last word the upgrade page gives.

**Fix:** add "Upgrading to 1.9.0" — closed default, `exposure` renames (`'read-only'`→`'closed'`, `'introspection'`→`'all'`), one-line restore (`expose: 'all'` dev / `expose: { roots, actions }` prod). Mark the 1.8.0 paragraph superseded.
