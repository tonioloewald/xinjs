## Blocker

### B1 — security — `describe()` publishes `href` (and `checked`, `placeholder`, `title`-derived `label`) in cleartext past `data-tosi-secret`

`src/agent.ts:1525-1570` (`describeElement`) · **verified, and re-reproduced in this triage on HEAD**

`describeElement(el, withheld?: ContentGuard)` writes the attribute harvest straight off the element *before* any secrecy decision, and the `withheld` guard it already receives is consulted only inside `referencedText()` and `associatedLabel()`. Reproduced under happy-dom with bounds mocked, `expose: { roots: ['app'] }` — the posture the docs call the production floor:

```
WIRING: [ { "tag":"a", "id":"m",
            "href":"https://x/reset?token=T",
            "text":"⟵ app.name", "bounds":{…} } ]
```

The marker is on an ancestor `<div data-tosi-secret>`. `text` was correctly withheld on the *same element in the same call* (it returns the binding arrow, not `go`) — **the response contradicts itself**, and there is no `secret: true` on the record, so a consumer cannot even tell something was suppressed. Two further shapes reproduce: marker directly on the anchor yields `read('c2.token') → "⟨secret⟩"` beside `describe()` emitting `href:"/reset?t=TOK-999", secret:true`; and `<input type="checkbox" data-tosi-secret>` emits `checked:true` beside `secret:true`.

**Reachability:** `src/webmcp.ts:138` gates `tosi_read`/`tosi_changes` behind `canRead`, but pushes `tosi_describe` unconditionally. So the surface hands a model-context host — a different principal — exactly the value the read gate exists to withhold.

**Why it blocks despite being pre-existing:** this is the seventh address of the invariant the `ContentGuard` parameter was introduced to close (`boundValue`, `redactWithin`, three `describe()` harvests, the structural tier, `associatedLabel`), the guard is threaded into this function and simply not asked, and *cleartext-secret leaks through `tosi_describe`* is the exact wording of the 1.8.3 blocker (`reviews/1.8.3-round3.md:15`). The fix is local and the tag has not been cut.

**Coverage is structurally incapable of failing on it:** `src/agent.test.ts` has 17 `data-tosi-secret` tests and two token-in-href fixtures (~991, ~1090), but both anchors are **unwired**, so those assertions pass for an unrelated reason. Nothing in the suite combines `data-tosi-secret` with `href`.

**Required before tag:**
1. In `describeElement`, withhold `href` and `checked` (and reconsider `placeholder`/`title`→`label`) when `referencedNodeIsSecret(el)` or `withheld?.(el) === true`; set `record.secret = true` in the *region* case so suppression does not read as absence.
2. Three tests — marker on the anchor, marker on an ancestor region, wired-by-in-scope-binding under `expose: { roots }` — each asserting the **token substring** is absent from `JSON.stringify(describe())`, not that a field is absent, so the next harvest added inherits the check.
3. Do **not** route through `contentWithheld` wholesale: its scope arm is broader than secrecy and would over-suppress ordinary hrefs. Re-review scope on remediation: security + correctness over the diff only.

## Major — scheduled, not gating

### M1 — security — inline-contract validation on `agent.write()` is fail-open on DOM presence

`src/agent.ts:1603` (`inlineSchemaFor`) · **verified in this triage**

```
mounted:  REFUSED — inline contract violation at "app.qty": expected one of [1,2,3]
detached: ACCEPTED
read:     "not-a-number"
```

Same call, same agent, same posture (`expose: { roots:['app'], write:true }`); the only change is `inp.remove()`. `inlineSchemaFor()` resolves the governing schema by scanning `document.getElementsByClassName(BOUND_CLASS)`, so enforcement is a function of what is currently rendered. In this stack that is not an edge case — `bindList` recycles rows, so a per-row inline contract binds only while the row is in the viewport; SPA route changes and hidden tab panels do the same. Nothing announces the downgrade (contrast `warnIfFailsOpen` in `contract-check.ts`).

Not elevated to blocker, and the reasoning matters: `describe()` scans the same live set, so at any single instant the map does not advertise what `write()` will not enforce — the finding's framing against the `agent.ts:2513` invariant overstates it. The real cost is that validation coverage tracks rendering. It also requires an agent already granted `write`, and the DOM-independent `expose.contract` curation — the documented production posture — supersedes inline declarations and is unaffected. `TODO.md:1056` tracks `inlineSchemaFor()` as an *efficiency* item only, so this is untracked as a gate issue.

Cheapest honest remediation, and worth landing in the same commit as B1 since both are in `agent.ts`: document in the agent doc block and the `contract` prop docs that inline contracts bind only while the declaring element is live, name `expose.contract` as the DOM-independent alternative, warn once from `write()` when a path lies under an uncurated root that no live element claims, and add a test that writes an invalid value with the element detached. The durable fix — remember `path → schema` at the declaration site (`elements.ts:790`, where `anyInlineContracts()` already keeps a module-level flag) with the DOM scan as fallback — is a follow-up.
