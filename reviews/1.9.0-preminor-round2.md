## Blockers

### B-1 — The manifest posture publishes the values `read()` refuses _(security + correctness, verified, `src/agent.ts:1789` / `:1794`)_

Merged from three lens reports (the security blocker, the correctness "two adjacent harvests disagree" major, and the completeness gap on structural scoping). Verified by execution end-to-end through `tosi_describe`, using the production posture verbatim from `agent-surface.md:269`.

With `enableAgentInterface({ expose: { roots: ['app.cart'], write: true } })`:

- `agent.read('session.csrf')` → throws `"session.csrf" is not exposed (manifest mode)` ✓
- `tosi_describe.execute({})` → `wiring: [{tag:'a', href:'/reset?t=RESET-TOKEN', text:'CSRF-TOKEN-8f31', …}, {tag:'div', contentEditable:true, text:'patient SSN 123-45-6789', value:'patient SSN 123-45-6789', …}]`

Three lines interacting:

1. `:1667` `if (!inScope(b.path)) continue` runs **before** `:1689 boundPaths.push(b.path)`, so out-of-scope bindings are never recorded — `suppressHarvest`/`harvestWouldLeak` therefore cannot know the element is bound to an undeclared or secret path, and their DOM arm finds nothing because the element is not a secret _control_.
2. `:1789` `if (record.href != null && record.tag === 'a') wired = true` — gated on nothing but the walk-level `!closed`.
3. `:1794` contenteditable — same, and it then harvests live `textContent` into both `text` and `value`.

The remediation implemented option 2 of B-1's fix (one `!closed` gate on the walk) rather than option 1 (gate the four `wired = true` sites on `scoped`). The closed posture is genuinely closed now; the manifest posture retains the exact contradiction the first review named as the tell — `:1774`'s unbound-form-control harvest **is** gated `!scoped`, with the comment _"an allowlist that hides `read('app.pin')` must not hand the same digits over as DOM content"_, while ten lines below an undeclared contenteditable's identical content is published.

Reaches a **different principal**: `tosi_describe` sits in the unconditional base tool array (`src/webmcp.ts:104`) with no posture gate, unlike `tosi_read`/`tosi_changes` at `:138`.

**Docs falsified as shipped:** `CHANGELOG.md:41-43` ("Undeclared state is now **absent, not redacted**: it never enters the map, the elements bound to it never appear in `wiring`") and `agent-surface.md:270/280`.

**Fix:** gate `wired = true` at `:1789` and `:1794` on `!scoped` (or on all bound paths being `inScope`); separately, make the harvest guards see _all_ bound paths (the structural tier already does this via the unfiltered `bindingPathsOf` — the main walk's scope-filtered `boundPaths` is the inconsistency) and have `suppressHarvest` refuse when any bound path is out of scope, not only when it is secret. Add the manifest-posture twin of the strengthened closed-posture fixture at `agent.test.ts:961`, with positive controls.

> Note: no test currently exercises these two shapes under a manifest — both features are tested only under `expose: 'all'` (`agent.test.ts:857-903`), so gating them breaks no asserted contract.

## Majors — fix before tag

### M-1 `exerciseContract()` reports a false green today _(correctness + blast-radius + security, verified — three lens reports merged, `src/contract.ts:155`)_

`refusedBySurface` matches the prose `'exposes nothing' || 'reading only' || 'not exposed'`. Two independent verifications found it is worse than "will drift":

- **All three substrings are currently dead.** `describe().writable` is literally `writesAllowed`, and `exerciseContract` throws up front when false, so `assertMutable`'s two messages are unreachable. `read()` calls the same `assertScope` as `write()`, and the loop already `continue`s on that failure, so `'not exposed'` is unreachable too.
- **The refusal that _is_ reachable is not in the list.** `src/agent.ts:2072-2077` throws `"<path>" is callable, not writable (declare it under roots to allow writes)` whenever the written path hits or contains a declared action. Matching nothing, `refusedBySurface` is false and the catch sets `passed = true`.

Reproduced: `expose: { roots: ['p1'], actions: ['p1.checkout'], write: true }` with a `$counterexamples`-only contract on the root → `exerciseContract` returns **`{ passed: 2, failed: 0 }`**, byte-identical to a genuinely-validated run. This is a **public API consumers run in their own CI**, and the surrounding comment exists precisely to prevent this outcome. No test covers `refusedBySurface` at all.

**Fix:** stop matching prose. Throw a tagged refusal from `assertScope`/`assertMutable`/the writable guard (`AgentScopeError`, or `err.tosiRefusal = 'scope' | 'mutability' | 'callable'`) and match the tag in `contract.ts`, keeping the substring list only as a fallback. Add a test asserting each thrown message is matched.

### M-2 `aria-labelledby` / `aria-describedby` launder `data-tosi-secret` _(correctness, verified, `src/agent.ts:1178` and `:1220`)_

`describeElement` builds `record.label` and `record.description` from `referencedText()` — `getElementById(id).textContent`, following an id to **any** node in the document — before any secrecy check, and no gate is ever applied to those two fields. `harvestWouldLeak`'s DOM arm is `el.querySelector(SECRET_CONTROL_SELECTOR)`, a _subtree_ query, so a referenced node outside the subtree is invisible.

Verified three ways. Structural tier under `expose: { roots: ['pubM'] }`: `<span id="m-secret" data-tosi-secret>LBL-SECRET-M</span>` + `<h2 aria-labelledby="m-secret">` → `{"tag":"h2","label":"LBL-SECRET-M","structural":true,"text":"Section"}`. Same in `recordFor` for both `label` and `description`. **Stronger than filed:** it also launders path-derived secrecy — an element whose own record is correctly suppressed has its live value republished as a neighbour's `label`.

Pre-existing, not a regression — but it is the same laundering the diff just closed for `textContent`, and the new structural-tier test asserts only the _descendant_ shape.

**Fix:** make `referencedText()` fail closed — if the referenced element matches `SECRET_CONTROL_SELECTOR` (or contains a match), return `undefined` and set `record.secret = true` so suppression is marked. One site fixes both fields.

### M-3 A self-declaring custom element publishes its whole contract under a manifest that declares nothing about it _(security, verified, `src/agent.ts:1835`)_

`if (record.component != null) { wired = true }` — no posture test — and `:1843` then folds in `_describedAttributes()` defaults. Verified: a `<priv-widget>` with `static contract = { description: 'internal admin panel — kill switch', actions: { wipe }, attributes: { adminToken: { default: 'abc-123' } } }`, no bindings and no handlers, appears in `describe().wiring` under `expose: { roots: ['pub'] }` with description, action namespace and attribute defaults intact.

This is the same class the event-handler gate at `:1683-1697` was fixed for this release ("an allowlisted surface published the private action namespace"). Genuinely uncertain: writing a `static contract` is arguably consent to be described (CLAUDE.md documents it as feeding the agent surface). But nothing says a contract opts a component _out of manifest scoping_, and the same argument would have justified the handler leak that was fixed.

**Decide and write it down**: either gate `:1835` on `!scoped || <tag or bound paths declared>` (leaving `expose.components` as the explicit opt-in), or state in `agent-surface.md`'s manifest tier and the `static contract` docs that a self-declared contract is published in every non-closed posture regardless of `roots`, so authors know not to put anything sensitive in a contract `description` or attribute `default`.

`d459382` + `648122e` close tosijs#31 (verified: the reported warning no longer fires on `listBinding()`, `textContent: proxy`, or `div(proxy)`), but the issue is OPEN with 0 comments, tosijs-ui#127 is OPEN with 0 comments, and UPSTREAM.md has no entry.
