## Blocker (fix before tag)

### B-1 — docs — the cleartext-secret CHANGELOG entry never names the affected shipped versions, and the only version it does name was never released
`CHANGELOG.md:64` (§ *Security — `describe()` published secrets in cleartext through the attribute harvest*). **Verified.**

The entry says the leak is "Pre-existing — the code is untouched by the rest of this release — and found by a scoped re-review of the remediation", and compares it to "the 1.8.3 blocker". **There is no 1.8.3 release** — tags go `v1.8.2 → v1.9.0`, and `1.8.3` is a review-round label (`reviews/1.8.3-*.md`). So the one number a reader can act on points at a version they cannot have.

The leak really shipped: `describeElement` harvests `href` unconditionally, before any secrecy check, in every released version from **1.8.0 through 1.10.1** (`v1.10.1:src/agent.ts:1539` — `const href = el.getAttribute?.('href'); if (href) record.href = href`, with `record.secret = true` set ~15 lines later, so the record carries both; identical unguarded pair at `v1.8.0:782`). `data-tosi-secret` is honoured in all of those versions, so a consumer who marked a password-reset region reasonably believes they were protected. HEAD fixes it at `src/agent.ts:1822` (`if (href && !secretHere)`).

**Why it blocks despite being a text edit:** `tosi_describe` is registered with model-context hosts unconditionally (the entry says so itself), so "did my version publish the magic-link token to a WebMCP host?" is an upgrade-urgency question, and the entry as written reads as "caught before it shipped". The omission is inconsistent *within the same release* — the sibling `#41` entry 90 lines down says "Present in every released version; verified back to v1.10.1" (`CHANGELOG.md:156`) — so it is not house style, it is a gap. 1.11.0 is untagged; this is fixable in one sentence.

**Fix:** add to the § at line 64 — *"Affects every released version that harvests `href`/`placeholder`/`title`: 1.8.0 through 1.10.1. Fixed in 1.11.0."* — and replace "the 1.8.3 blocker" with wording that does not read as a version (e.g. "the blocker found in the 1.8.x review cycle that shipped as 1.9.0"; the same phrase also appears at `CHANGELOG.md:852`). **RE-REVIEW SCOPE: Tier 0 only.**
