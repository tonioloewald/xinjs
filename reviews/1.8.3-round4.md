## BLOCKER

### B-1 · `describe()` publishes secrets through its live-DOM harvests — the invariant this release exists to restore

`src/agent.ts:1449` (the `record.text` fallback) and `src/agent.ts:1480` (the contenteditable branch) consult **no secrecy signal at all**. The unbound-form-control harvest three lines between them, at `:1459`, does gate on `record.secret !== true` — so the guard is simply missing on the other two.

Re-reproduced on the current working tree (read-only default posture, `enableAgentInterface({ global: false })`), all three shapes:

```
SHAPE1 {"tag":"div","id":"show3","detail":[{"path":"probeTok.token",…}],"text":"eyJ-SUPER-SECRET"}
       …while read('probeTok.token') → "⟨secret⟩" in the SAME session
SHAPE2 {"tag":"select","id":"sel2","secret":true,"value":"⟷ probeSel.card",
        "text":"4111 1111 1111 11115555 5555 5555 4444"}
SHAPE3 {"tag":"div","id":"ed3","contentEditable":true,"secret":true,
        "text":"sk-live-DEADBEEF","value":"sk-live-DEADBEEF"}
```

Shape 2 stamps itself `secret: true`, correctly redacts `value`, and prints the card numbers beside it in the same object. Shape 3 is the author's own documented `data-tosi-secret` opt-in being ignored.

**Wider than the finding stated.** Verification also found it leaks in **manifest** posture — the posture the CHANGELOG recommends for production: a plain `<div>` wired only by a click handler harvested its _subtree's_ textContent from a `data-tosi-secret` contenteditable child. Any wired ancestor launders a secret descendant's text.

Reachable through `tosi_describe`, the one WebMCP tool registered in **every** posture, and through `globalThis.tosiAgent` from any script on the page. Not covered by the CHANGELOG's `#32` caveat — that is scoped to path _spelling_; this mechanism never consults a path.

**Remediation, and the two traps in it:**

1. Gate both harvests. `record.secret === true` **alone is not enough** — shape 1's `record.secret` is absent by construction. The guard must be `record.secret === true || <any bound path on this element> isSecretPath(...)`, keyed on the same signal as `boundValue()`.
2. That still leaves the ancestor case. Either test the subtree for secret controls / `data-tosi-secret` regions before harvesting `textContent`, or drop the text harvest for any element with secret-bearing descendants.
3. When suppressed, keep `secret: true` on the record so consumers can distinguish redaction from absence.
4. Pin it the way SEC-2b pins `boundValue`: one test per shape (custom textContent binding, secret `<select>` option text, contenteditable + `data-tosi-secret`, **and the wired-ancestor case**) asserting `JSON.stringify(record)` does not contain the plaintext.

Reproductions: `<scratchpad>/probe.test.ts` (3 shapes) — currently 0 pass / 3 fail.

_Pre-existing in 1.8.0–1.8.2. That does not lower severity: 1.8.3/1.9.0 exists to make `describe()` stop publishing what `read()` refuses, and shipping that claim with the mechanism open would be the third consecutive false disclosure in this cycle._

## MAJORS (do not block, but do not ship silently either)

### M-1 · `agent.read()` is quadratic in the size of a secret-bearing collection _(verified; severity flagged uncertain by both reviewer and verifier)_

`src/agent.ts:831`. Independently reproduced: 4× wall time per 2× N, consistently (N=200→400→800 = 30.7 / 114.8 / 450.5 ms; reviewer measured up to 985 ms at N=800 on slower hardware). Two multipliers, both confirmed by instrumentation:

- `redactWithin` is called exactly **3N+1** times — all three candidate spellings pass `containsSecret`, so every row is deep-cloned and re-walked three times; two clones exist only to be discarded.
- Predicates run **21N** times, each an O(|secretPaths|) linear scan → ~21N² `extendsPath` calls.

Attribution isolated: with N rows but only **one** registered secret the same benchmark is exactly linear, so the quadratic is the `|secretPaths|` scan repeated per row. Amplifier the finding did not name: `secretPaths` is session-lifetime append-only, so a long-lived SPA paging a large vault degrades monotonically and never recovers.

Agent-surface only, opt-in, invisible outside a credential/vault-shaped list. `describe()` and `changes()` unaffected.

### M-2 · The agent surface's redaction — and its known incompleteness — is documented everywhere except the page a developer enabling it reads _(verified)_

`src/agent.ts:2-61` is byte-identical to 1.8.2 and mentions secrets **zero** times; so does the rendered `docs/agent/index.html`. `⟨secret⟩`, `data-tosi-secret` and `#32` reach no rendered doc — only CHANGELOG, TODO.md, source comments and the GitHub issue, all upgrade-time or maintainer-facing. Meanwhile the same doc block advertises auto-registration with `document.modelContext`. `trust-and-transports.md` — indexed in `llms.txt` as "the honest section … secrets" — describes redaction in the _aspirational_ mood, so a reader concludes it is unbuilt.

**This is the third round it has been filed**: `reviews/1.8.3-round3.md:111` carries it verified/major with the same remedy, unactioned through two releases. Fix is prose — a `## Secrets and disclosure` block in the `agent.ts` doc block plus the same paragraph in `agent-surface.md`. Cheap enough to do alongside the blocker fix.

### M-3 · Migration guide — **mostly moot after the walk-back**, one residual

The verified finding (no `1.9.0` section for a deliberately-minor release) is dissolved: the `listBinding` shape break is reverted and the release is a patch again. **Residual, downgraded to minor:** `ElementProps.bind` is still widened to `TosiInlineBinding<T> | Array<TosiInlineBinding<T>>` in `src/xin-types.ts:300` and in the shipped `dist/xin-types.d.ts:215`. Writers are unaffected; any reader of `props.bind.value` on an `ElementProps`-typed value now fails to compile — a compile-time break shipping in a **patch**, filed under "Changed". Either note it in the CHANGELOG as a type-level break or accept it explicitly.
