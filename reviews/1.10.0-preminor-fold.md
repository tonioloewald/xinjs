## Blockers (all adversarially verified)

### B1 — correctness — The headline migration path "`withAttributes` base + subclass `initAttributes` compose" is false, and ships in three artifacts

`src/component.ts:1320` (`_resolveInitAttributes`, no-contract path)

`class Base extends withAttributes({ label: 'base' })` then `class Sub extends Base { static initAttributes = { extra: 7 } }`:

- **Runtime:** `Sub._resolveInitAttributes()` → `{"extra":7}`; `observedAttributes` → `["hidden","extra"]`; `sub.label` → `undefined`; `sub.setAttribute('label', …)` still leaves it `undefined`. The base's attribute is dropped from the instance _and_ from `observedAttributes` — reflection severed both directions, **no throw, no warning**. Cause is a bare `return this.initAttributes` (a static lookup, so a subclass's own static shadows the parent's entirely). The **contract** branch 20 lines above (`src/component.ts:1293-1310`) does exactly the prototype-walk merge that is missing, with a comment saying a subclass "must not silently drop the base class's initAttributes".
- **Types (`tsc --strict`):** `TS2417 Class static side 'typeof Sub' incorrectly extends base class static side 'typeof Base'. Property 'label' is missing` plus `TS2339: Property 'extra' does not exist on type 'Sub'`. The spread workaround clears TS2417 and works at runtime but still gives TS2339 on `this.extra` — reinstating the untyped-attribute problem `withAttributes` exists to solve.
- **Ships in:** `Migration.md:110-112` (inside "What does NOT change" — the section an upgrader trusts most), `CHANGELOG.md:155`, `src/component.ts:399-402` (inside the `/*# … */` block, therefore live on `docs/component/index.html`, in `docs/docs.json`, and in `docs/tosijs.epub`), and `CLAUDE.md`.
- **Pinned by nothing:** `src/component.test.ts:2415-2445` uses the spread _and_ `as any` on both classes, so it asserts neither failure and passes.

**Fix — pick one:**
(a) mirror the contract branch's merge onto the no-contract path and correct the type story. _Re-review scope: correctness + blast-radius over the remediation diff only — merging inherited `initAttributes` changes `observedAttributes` for every subclassed component in the ecosystem._
(b) if the merge is judged too risky for a minor, rewrite all four prose sites to document the shape that actually works (spread the base map **and** `export interface Sub extends ComponentAttrs<typeof Sub.initAttributes> {}`) and drop the `as any` casts from the extended test so it pins the shape. _Re-review scope: Tier 0 plus a correctness spot-check that the documented shape typechecks._

Do not leave the sentence as written.

### B2 — security — Secret redaction is light-DOM only: a password inside a component's shadow root reaches `read()`, `changes()` and `describe()` in cleartext

`src/agent.ts:1137` (`refreshSecretPaths`)

`refreshSecretPaths()` learns secret paths from `document.querySelectorAll(SECRET_CONTROL_SELECTOR)`, which does not pierce shadow roots — `grep -n 'shadowRoot|getRootNode' src/agent.ts` returns zero hits. But the _write_ side deliberately crosses the boundary (`bind.ts:503 closestAcrossShadow`), so typing into a shadow password field writes to state normally. Verified by execution, three ways:

- Same page, same state shape: shadow `<input type="password">` → `agent.read('app.creds.password') === "hunter2"`, `read('app.creds')` → `{"password":"hunter2"}`; light-DOM equivalent → `"⟨secret⟩"`.
- `agent.changes()` returns the cleartext delta unredacted.
- **It reaches the _supported_ pattern, not an exotic one:** a Component with `shadowStyleSpec`, bound from outside with `bindings.value` — exactly what `component.ts:2648`'s own warning instructs — produces `describe()` wiring `{"tag":"pw-field","value":"hunter2 ⟷ app.a.password"}`. That is the plaintext itself, inside the output the module doc says is "designed to leave the machine … typically an off-device one", and which `enableAgentInterface({ expose: 'all' })` auto-publishes to a WebMCP host as `tosi_read` / `tosi_changes`.

The doc block states the guarantee **unconditionally** (`src/agent.ts:67`: "A path bound to a password field … is withheld") and names the only known gap as "exotic spellings of a direct query" (`:97`). No test covers it — `src/agent.test.ts` has ~15 secret tests and **zero `attachShadow`** — so the suite is green while the guarantee is false.

Two corrections to the reported framing, neither of which refutes it: tosijs Components do **not** default to shadow DOM in this codebase (`component.ts:2637` attaches only when `shadowStyleSpec`/`styleSpec`/`styleNode` is set) — but styled components are the common case; and marking the **host** `data-tosi-secret` _does_ work when the host is itself bound (the skip at `:1144` only applies to unbound elements) — so a cheap mitigation exists, but it is undocumented as necessary and undiscoverable.

Latent since 1.8.0 (`git show v1.8.0:src/agent.ts:712` has the identical document-scoped scan). **That does not make it shippable**: this release re-asserts the guarantee and widens the surface that leaks it.

**Fix (architectural, preferred):** iterate the bound elements the library already indexes (`getElementsByClassName(BOUND_CLASS)` plus a recursive descent through open `element.shadowRoot`) and ask `isSecretControl` per element — which also addresses the perf note already in the comment above `refreshSecretPaths`. **Minimum to unblock the tag:** recursive open-shadow-root descent in `refreshSecretPaths`, _or_, if the architecture is deferred, correct the guarantee text to name shadow DOM explicitly and document `data-tosi-secret`-on-the-host. Closed roots are unreachable and should be stated as such. Add an `attachShadow` case to the secret suite for both a shadow password input and a shadow `data-tosi-secret` node, and **mirror it in the Playwright lane** — happy-dom must not be the only witness.
_Re-review scope after fix: security (re-verify across open roots, closed roots and nested hosts **by execution**), efficiency (the scan runs on EVERY read; a recursive walk must not reintroduce the 350µs–2ms cost the existing comment measured), plus correctness over the remediation diff._

### B3 — blast-radius / packaging — `tosijs/debug` and `tosijs/safe` resolve to files that are absent from git and that every `bun start` deletes

`bin/site.ts:232`; `bin/bundles.ts`; `package.json` `exports`

- **Mechanism:** `BUILT = full ? BUNDLES : BUNDLES.filter(b => b.stage !== 'tjs')`; `keepJs = new Set(BUILT.map(b => b.naming))`; the strip loop below unlinks every `dist/*.js` not in `keepJs`. Both tjs-stage bundles are therefore **deleted by any dev run**. Dry-ran the exact logic against the real `dist/`: _"DEV RUN WOULD UNLINK: [module.debug.js, module.safe.js]"_.
- **Already fired:** `git show 5229813 --name-status` → `D dist/module.debug.js`, `D dist/module.safe.js` — a deletion that commit's message never mentions (it claims "`bun run build` is unchanged"). Confirmed now: `git ls-files dist | grep module.debug` → empty; `ls dist/module.debug.js` → **No such file**. They are not even on disk at HEAD.
- **Declarations still live:** `exports["./debug"] → ./dist/module.debug.js`, `exports["./safe"] → ./dist/module.safe.js`; `files` ships `/dist` with only the two `.map`s negated (which only makes sense if the `.js` are meant to ship); `CLAUDE.md:62` documents both; the CHANGELOG says nothing about retiring them. **This is collateral, not a decision.**
- **The documented release order guarantees the bad state.** `playwright.config.ts` sets `webServer.command: 'bun start'` (no `--build`), and `bun run test:browser` is **step 4** of the release checklist — run after step 3's `bun run build` and before step 6's commit and step 8's `npm publish`. Build creates them; the browser lane deletes them; publish ships without them. Because they are now **untracked**, `git status` no longer reports the loss the way it did when they were tracked. Reproduced this session: present before `bun run test:browser`, gone after.
- **No gate can see it.** The smoke loop and the gzip-budget loop both iterate `BUILT`. `src/entries.test.ts:314` is `if (!existsSync(…)) continue` — a missing bundle is silently skipped. `entries.test.ts:272` asserts only that each `exports` target is _declared_ in `BUNDLES`, never that the file exists. The `.pack-probe` gate measures unpacked size against a _ceiling_, so a tarball missing ~120 kB of artifacts passes more comfortably. `prepublishOnly` checks only the dist-tag.
- **Also breaks git-dependency installs:** there is no `prepare` script, so `bun add github:tonioloewald/tosijs` at HEAD yields `ERR_MODULE_NOT_FOUND` for `tosijs/debug`.

**Fix, three layers, cheapest first:**

1. Rebuild and **commit** both bundles so the tree matches `exports` — _or_, if they are meant to go, remove `./debug` and `./safe` from `exports`, drop the `files` map exclusions, and say so in CHANGELOG + Migration.md (they are documented, consumer-reachable, experimental API).
2. Stop the dev run destroying artifacts it did not build: the strip loop exists to remove tsc's per-file emissions, so strip only those (or intersect with the **full** `BUNDLES` naming set). `BUILT` is right for smoke and budgets and wrong for deletion.
3. Add the general gate next to the budget test in `src/entries.test.ts`: **every `.js` target reachable through `pkg.exports` must `existsSync` whenever `dist/module.js` exists.** That closes the class, not just these two files.

_Proportionality note: actual consumer damage is modest — both bundles are documented EXPERIMENTAL and inert, and likely have no real users. It blocks because the mechanism is silent, deterministic, recurring, invisible to every gate, and trivially fixable._
_Re-review scope: correctness + blast-radius over the remediation diff only (the strip-loop change is behavioural)._

## Majors (verified; fix now or file as scheduled follow-ups)

### M1 — correctness + security (deduped: reported independently by both lenses) — `agent.observe()` classifies a function-valued state proxy as a filter predicate, so observing an action **invokes** it on every settled touch, unaudited

`src/agent.ts:2474`

`const pattern = pathRef instanceof RegExp || typeof pathRef === 'function'` is evaluated **before** `toPath`. A tosijs boxed proxy over a function reports `typeof === 'function'` (`xin.ts:1281-1307` returns `new Proxy(value.bind(target), …)`, and a Proxy preserves the target's typeof, with no `apply` trap). So the action proxy is handed to `observe()` as a path **filter** and called for every touch.

Reproduced: with `expose: 'all'`, `agent.observe(app.boom, cb)` then `app.n.value = 1` → `boom` invoked with `["app.n"]`; 5 writes → 5 invocations, for the life of the observer. The caller's `cb` never fires (it fires only if the action returns truthy). `assertScope` is skipped by construction; `assertMutable('call', …)` never runs; **the ledger records only the touches, no `call:` entry** — so the invocations are invisible to audit, unlike a real `agent.call()`. Typechecks clean under `--strict` (`AgentObserveRef` admits it as the predicate arm), so nothing warns.

Under a manifest the same call is refused, but with a message that misdirects: _"observe() takes a pattern (RegExp or predicate) only under `expose: 'all'`"_ — for a caller who passed an ordinary path ref (`tosiPath(p.go)` → `"p4.go"`). The two postures disagree about what `observe(proxy)` even means.

The runtime hazard is not strictly new (v1.9.2's `observe(path: string, …)` also passed its argument straight through), but it is **newly invited and type-legal**: the release headline is "the agent surface takes proxies, not just path strings", and the doc comment at `agent.ts:26` was rewritten from `agent.observe('app.cart', …)` to `agent.observe(app.cart, …)`. Under 1.9.2 the same call was a type error. Realistic path: `describe()` publishes `actions: ['app.saveOrder']`, an agent observes what it just discovered, `saveOrder('app.n')` runs on every keystroke.

Not privilege escalation (`expose: 'all'` already permits `call`), but it is unintended, unaudited, repeated side-effect execution driven by state rather than by the caller.

**Fix (one line):** resolve the path first — `const asPath = typeof pathRef === 'string' ? pathRef : tosiPath(pathRef); const pattern = asPath == null && (pathRef instanceof RegExp || typeof pathRef === 'function')`. Add a test that `observe(<action proxy>, cb)` observes the action's path and does **not** invoke it, under both `expose: 'all'` and a manifest. Neither of the three new observe tests (`agent.test.ts:2553-2614`) passes a function-valued proxy.

### M2 — correctness — `disable()`-now-revokes kills the release's own showcase doc page after two clicks

`docs/agent-surface/index.html` (source: `agent-surface.md` fences at 31 / 396 / 471)

Three live ```js fences share one realm (tosijs-ui runs them via `new AsyncFunction`with the page's module in`this.context`— same globalThis, same module instance; these fences are not`mode="iframe"`, and tosijs-ui's own docs note even iframe mode does not isolate tosijs state). Fence 2 captures `const agent = globalThis.tosiAgent ?? enableAgentInterface({expose:'all'})`**at load**. Fence 3 calls`enableAgentInterface`three times inside its click handler, and`enableAgentInterface` auto-disables the previous surface — which since this release **revokes** it (`assertLive`, new in this diff; absent from `v1.9.2:src/agent.ts`).

Replayed the two-click sequence: click "dev day vs ship day", then "agent tries qty = 'lots'" → `write()` throws `tosiRefusal: 'revoked'`, the catch runs, and **`agent.log()` throws `revoked` from inside the catch** — uncaught exception, `out` never updated, example permanently dead (`agent` is a captured `const`). The sibling "exercise it" button fails identically via `exerciseContract(agent)` → `describe()`. Under 1.9.2 both kept working. `docs/derived-surface/` is unaffected. The CHANGELOG already states the remedy ("re-read `globalThis.tosiAgent`"); the project's own examples do not follow it.

**Fix:** in the `/*# … */` source, read `globalThis.tosiAgent` **inside** each click handler rather than capturing it at load (or have the reconfiguring example restore and re-publish the handle). Rebuild `docs/` + epub. See also the ungated-live-examples follow-up below — nothing currently executes ```js fences, which is the same hole that let the 1.10.0 `dynamic(this)` blocker ship.

### M3 — efficiency — `main.js` has 17 bytes of gzip headroom, so the size gate is hair-trigger

`bin/bundles.ts:97`

Measured with the gate's own basis (Bun `node:zlib` `gzipSync`, the call `bin/site.ts:355-356` makes), on a committed `dist/` re-derived byte-identically from source:

| bundle            | gz     | budget         | headroom |
| ----------------- | ------ | -------------- | -------- |
| `main.js` (CJS)   | 43,483 | 43,500 (`:97`) | **17 B** |
| `module.js` (ESM) | 43,196 | 43,500 (`:88`) | 304 B    |

CJS runs 287 B over ESM at HEAD (271 B at v1.9.2), so **equal ceilings structurally cannot give equal headroom** — which invalidates the comment at `bundles.ts:84-89` that justified raising module.js to match main.js. This release grew `main.js` by 577 gz bytes and consumed all but 17 of them; the ESM budget was raised in-commit, the CJS one was never looked at. The file forbids exactly this, twice (`:48-56`, `:120-134`): _"a gate that passes by a hair fails next week on something unrelated and teaches whoever hits it to raise the number without reading it (1.8.1 shipped one that passed by SEVEN bytes; that is the mistake not being repeated)"_.

Worse than reported: the budget loop is **not** guarded by the `full` flag, so the next ~20 gz bytes anywhere in the library breaks **`bun start` for every developer**, not just the release gate. Nothing else catches it — `src/entries.test.ts:308-316` asserts only `bytes > budget`, never a minimum headroom.

_Correction to the headline: the gate is not "dead", it is hair-trigger — it will fire loudly on the next unrelated edit. The harm is the false alarm that trains budget-bumping._

**Fix:** set `main.js` to ~44,500 in this same commit, with a note that CJS runs ~290 gz bytes over ESM so the two ceilings are deliberately **not** equal. Better: express budgets as `measured + 1024` per bundle rather than hand-copying one bundle's ceiling to another.
