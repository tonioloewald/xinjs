## Blockers (fix before tag)

### B-1 — `record.checked` is gated on element-local secrecy only, so `describe()` publishes in cleartext a value `read()` refuses
`src/agent.ts:1648` · correctness · **verified**

```js
const { p3 } = tosi({ p3: { twoFactorEnabled: true } })
const secretCb = input({ type:'checkbox', 'data-tosi-secret':'', 'aria-label':'2FA', bindValue: p3.twoFactorEnabled })
const mirror   = input({ type:'checkbox', 'aria-label':'mirror',              bindValue: p3.twoFactorEnabled })
```

`agent.read('p3.twoFactorEnabled')` → `"⟨secret⟩"`. `describe().wiring[1]` → `{tag:'input', label:'mirror', type:'checkbox', checked:true, value:'⟷ p3.twoFactorEnabled', secret:true, …}` — one record carrying `secret: true` **and** the value the read gate withholds. `radio` rides the same gate, so a radio group over a secret path leaks which option is selected.

`checked` is computed in `describeElement`, which runs before bindings are known and gates only on `secretHere` (element-or-ancestor). Every sibling channel consults path secrecy: `boundValue` does `if (secret || isSecretPath(path))`, `harvestWouldLeak` loops `isSecretPath(path) || containsSecret(path)`, `readScanned` returns the sentinel. The doc block added by **this diff** (`src/agent.ts:80-98`) names `checked` specifically as withheld and states "Secrecy is a property of the PATH … including from *other* elements bound to the same path." Both statements are false on HEAD.

Pre-existing relative to `ac9108b`, but unreleased, and it is the eighth address of the invariant this release exists to close.

**Fix:** do not add a ninth per-site restatement. `suppressHarvest` (`src/agent.ts:1465-1473`) is already the choke point that sets `record.secret = true` for path-derived secrecy — have it strip live-state fields (`delete record.checked`) so future fields inherit the guard by construction. Add `checked` to the token/field list in `describe(): secrecy covers the ATTRIBUTE harvest`.

> ⚠️ **A currently-green test asserts the leak.** `src/agent.test.ts:3196-3222` ("AND ORDINARY MAP DATA SURVIVES — the over-redaction control") binds a `<input type=password>` **and** a checkbox to the same path `ord.name`, then asserts `expect(w.find((r) => r.checked === true)).toBeDefined()`. The fix must re-point that toggle at a non-secret path to preserve the test's over-redaction intent — otherwise the fix reads as breaking a security test.

Pin with the mirror fixture: two checkboxes on one path, one marked, assert `JSON.stringify(describe())` contains no `"checked"` on either.

### B-2 — a light-DOM wrapper carrying the value binding over `<input type="password">` is never learned as secret; `read()`, `changes()` and `describe()` all return cleartext
`src/agent.ts:1590` · security · **verified** · *regressed by this diff*

Three-way A/B against the committed bundles (happy-dom, posture `expose: { roots: [app] }` — the documented production floor):

| rev | describe leaks | `read('app.pw')` |
| --- | --- | --- |
| v1.10.1 | yes | `CLEARTEXT-PASSWORD` |
| `ac9108b` | **no** | `⟨secret⟩` |
| HEAD | yes | `CLEARTEXT-PASSWORD` |

Two halves. (1) `refreshSecretPaths` walks up from the found control **only across a shadow boundary** (`el.getRootNode()?.host`, `:1301-1308`). In light DOM there is no `.host`, so the wrapper's binding is never harvested — this is why `changes()` leaks on `ac9108b` too, with no `describe()` involved, and is **pre-existing**. (2) Until this diff, `describeElement`'s `secretHere = referencedNodeIsSecret(el)` retroactively closed the *read* path via the containment arm → `record.secret` → `recordFor`'s `addSecretPath`. The round-4 narrowing removed that cover and nothing replaced it. The emitted record self-contradicts: `{"tag":"pw-field-light","value":"CLEARTEXT-PASSWORD ⟷ lightCreds.password","secret":true}`.

Reproduces for a plain `<form>` with any custom `fromDOM` binding over a contained password field, so it is not component-specific. Light DOM is a first-class Component mode per CLAUDE.md.

**The round-4 narrowing is correct and must not be reverted** — it fixed a real permanent over-redaction. The remedy is the light-DOM twin of the shadow arm, narrowed identically: in `refreshSecretPaths`, after the `host` block, walk `el.parentElement` upward (bounded to `document.body` or the nearest ancestor carrying a data binding) and `addSecretPath(b.path)` for bindings where `b.binding?.fromDOM != null`. The verifier instrumented the round-4 regression fixture: its `data-theme` binding reports `fromDOM: false`, so the discriminator separates the cases and this cannot reintroduce B-1. Prefer `refreshSecretPaths` over `recordFor:2215` — only that closes `read()`/`changes()` called before any `describe()`.

Pin with the light-DOM fixture in both postures, asserting on `read`, `changes` and the serialised `describe()`, alongside the three over-redaction controls (toDOM-only container over a password; over a `type="hidden"` CSRF input; shadow host with `bindings.text`).

### B-3 — the shipped CHANGELOG's Security entry names the helper this diff removed, and omits `aria-description`
`CHANGELOG.md:85` (and `:66-67`) · correctness · **verified**

`CHANGELOG.md:85`: "The fix asks the **secrecy** arm (`referencedNodeIsSecret`)". Shipped code at `src/agent.ts:1590` is `isSecretControl(el) || closestAcrossRoots(el, '[data-tosi-secret]') != null`, and the 30-line comment above it calls the named spelling "catastrophically wrong." The two differ on observable semantics — `referencedNodeIsSecret` is element-or-ancestor-**or-descendant** — and the very next sentence ("Over-redaction … one password field marked a whole state root secret, permanently") is true of the shipped code and **false of the implementation it names**. `reviews/1.11.0-round4-post-b1.md:29` records that the named implementation reintroduced precisely that bug.

`CHANGELOG.md:66-67` lists four withheld attributes (`href`, `placeholder`, `title`-as-`label`, `checked`). This diff added a fifth — `aria-description` / the `aria-describedby` arm (`src/agent.ts:1665-1670`) — unmentioned anywhere in the 1.11.0 section. `AgentWiringRecord.description` is a public field, and `src/component.ts:2585-2593` stamps `contract.description` onto `aria-description`, so a component's declared description now silently vanishes from `describe()` inside a secret region.

`CHANGELOG.md` is in `package.json` `files`; `docs/` and `llms.txt` are not, so this is the **only shipped prose** on the fix. Concrete failure: a maintainer implementing against the documented containment semantics reintroduces the round-4 path poisoning.

**Fix:** name the shipped predicate; state that containment does NOT imply secrecy and why (`record.secret` escalates to `addSecretPath`, module-level and append-only); add `aria-description`/`aria-describedby` to `:66` and note `contract.description` is covered.

### M-2 — the new gz-delta emitter prints a silently-incomplete "paste into the CHANGELOG" table on dev runs
`bin/site.ts:463-500` · correctness/blast-radius (2 lenses, merged) · **verified**

The block has no `full` gate (only `tag !== ''` and `rows.length > 0`) and iterates `BUILT` = `full ? BUNDLES : BUNDLES.filter(b => b.stage !== 'tjs')` (`:309`). `bun start` calls `buildLibrary(false)` (`:846`), so a dev run prints a **five-row** table under `gz delta since v1.10.1 — paste into the CHANGELOG:` with nothing indicating that `module.debug.js` and `module.safe.js` — the two largest deltas, +1032/+1029 — are missing. **This is exactly the two rows that are wrong in the shipped CHANGELOG today.**

Reachability is not hypothetical: `playwright.config.ts:37` sets `webServer.command` to `bun start`, so release-checklist step 4 emits the truncated table *after* step 3's correct one — the last "paste this" table in a release log is the incomplete one.

Two further holes: `if (show.exitCode !== 0) continue` (`:483`) silently drops any bundle absent at the previous tag (forcing `tag = v1.7.9` drops `core.js` and `state.js`, 1.8.0's two headline artifacts, from a table that looks complete); and `git describe --tags --abbrev=0` returns the tag **on** HEAD, so any rebuild after checklist step 6 emits an all-zero delta under the same authoritative caption.

The adjacent comment at `bin/site.ts:322` already records this distinction for the deletion loop — "BUILT is right for smoking and for budgets. It is wrong for deletion… the full set."
