## Fix before the tag (verified majors)

### 1. Variable-height list: changing the array above the built rows while scrolled moves the visible content (correctness, verified, severity uncertain)
`src/list-binding.ts:1908` (`_findAnchor`) and `_layoutVariable` (~1971–1989).
- **(a) `splice` above the viewport.** The anchor is the OLD row at the new `first` index. That row has just left the slice, so the code falls back to an estimate, and the content under the reader jumps by one card (192px measured in all three engines).
- **(b) `unshift` above.** The visible card stays put, but `exact` stays true while T is 300px short. Scrolling back to the top then snaps by up to 300px (≤8px without a mutation).
- **Impact:** this is not a regression, since v1.10.8 could not scroll here in Chromium at all. But it contradicts the CHANGELOG claim "a row that stays built keeps its place when others come and go", and it hits the motivating case: feed and kanban lanes such as virta (#3302).
- **Fix:** anchor on the first previously built element whose item survives into the new slice, matched by identity or idPath. On a non-slice update, set `exact = false` unless the rows above `first` provably did not change. **Fallback if you cannot do this today:** narrow the CHANGELOG and header-comment claim (src/list-binding.ts ~1166) to scrolling and whole-list replacement, and file the fix as the first task for 1.10.10.
- **Check that clears it:** add a case to `tests/virtual-list-jumps.pw.ts`. Scroll to the middle, then `splice(2,1)` and `unshift({h:300})` above the viewport. Assert the top visible card moves less than 8px, and that scrolling back to the top stays within 8px per step. It must fail with the fix reverted, in Chromium, Firefox and WebKit. Remember the browser-lane rule: commit dist first, then rebuild afterwards.

### 2. README Hot Reload section contradicts the rewritten hot-reload page (docs, verified)
`README.md:~510–512` says "hot reloading (and not just in development!)", says "you're good to go", and gives `localStorage.clear()` as the reset. `src/hot-reload.ts`, `llms.txt` and the CHANGELOG now say it is "not intended for production", that localStorage is readable by anything on the page, and that the reset is `localStorage.removeItem('xin-state')`. README is both the npm landing page and the site home.
- **Fix:** replace the README section with one or two sentences and a link to https://tosijs.net/hot-reload/, so the facts live in one place. At minimum, drop "and not just in development!" and fix the reset line.
- **Check that clears it:** `grep -n "not just in development\|localStorage.clear" README.md` returns nothing, and `bun run build` regenerates the docs cleanly. The edit is mechanical, so re-review covers Tier 0 only.
